## 1. 핵심 기술 개념 (엔지니어링 관점)

### 1.1 커널 레벨에서의 동작 원리

대규모 언어 모델(LLM) 및 파운데이션 모델의 학습 및 추론 과정은 운영체제 커널과 밀접하게 상호작용하며, 이는 하드웨어 자원의 효율적인 활용과 직접적으로 연결된다.

*   **프로세스 및 스레드 스케줄링:** 모델 학습은 수많은 병렬 연산을 포함하며, GPU 커널 실행 및 CPU 상의 데이터 전처리 스레드 관리가 핵심이다. 리눅스 커널의 CFS(Completely Fair Scheduler)는 각 프로세스/스레드에 가상 런타임을 할당하여 CPU 시간을 공정하게 분배한다. 대규모 분산 학습 환경에서는 `cgroups`를 통해 컨테이너별 CPU 사용량을 제한하고 우선순위를 조정하여 자원 격리 및 효율성을 관리한다. 컨텍스트 스위칭은 CPU 레지스터 및 MMU 상태를 저장하고 복원하는 과정이며, 이 오버헤드를 최소화하기 위해 `epoll`과 같은 비동기 I/O 메커니즘이 활용된다. eBPF를 활용하면 `schedule()`과 같은 커널 함수 호출을 추적하여 스케줄링 지연 및 CPU 사용 패턴을 실시간으로 모니터링하고 분석하여 병목 지점을 식별할 수 있다.
*   **메모리 관리:** LLM은 수십억 개 이상의 파라미터를 가지므로, 모델 가중치와 활성화 값 저장을 위해 테라바이트 이상의 데이터가 필요할 수 있다. 커널은 가상 메모리 시스템을 통해 물리 메모리 이상의 주소 공간을 제공하며, MMU(Memory Management Unit)는 가상 주소를 물리 주소로 변환한다. 페이지 폴트 발생 시 커널은 디스크의 스왑 공간에서 데이터를 물리 메모리로 로드하며, 이는 성능 저하로 직결된다. 대규모 모델의 경우, `mmap` 시스템 콜과 함께 `MAP_HUGETLB` 플래그를 사용하여 HugePages를 할당하면 TLB(Translation Lookaside Buffer) 미스율을 줄여 메모리 접근 성능을 향상시킬 수 있다. NUMA(Non-Uniform Memory Access) 아키텍처 환경에서는 `numactl` 명령어나 애플리케이션 레벨에서 CPU 코어와 물리적으로 가까운 메모리에 데이터를 할당하여 메모리 접근 지연 시간(latency)을 최소화하는 알고리즘 최적화가 필수적이다. eBPF는 `page_fault_user()`와 같은 커널 트레이스포인트에 후킹하여 페이지 폴트 발생 빈도 및 원인을 분석함으로써 메모리 관리 오버헤드를 진단하는 데 활용될 수 있다.
*   **장치 드라이버 및 가속기 관리:** GPU와 같은 하드웨어 가속기는 LLM 연산의 핵심이다. 커널은 GPU 드라이버(예: NVIDIA CUDA 드라이버)를 통해 사용자 공간 프로세스가 GPU 자원에 접근하고 연산을 수행하도록 중재한다. 사용자 공간 애플리케이션은 `ioctl` 시스템 콜을 통해 드라이버와 통신하여 GPU 커널을 실행하고 메모리 할당 및 복사 등의 작업을 지시한다. 드라이버는 GPU의 컴퓨팅 유닛, 메모리 컨트롤러, DMA(Direct Memory Access) 엔진 등을 직접 관리하며, 이 과정에서 `perf_event_open`과 같은 시스템 콜을 사용하여 GPU 성능 카운터를 모니터링할 수 있다. 멀티-GPU 환경에서는 NVLink와 같은 고속 인터커넥트가 PCIe의 대역폭 한계를 넘어 GPU 간 직접 데이터 통신을 가능하게 하여 분산 학습의 효율성을 극대화한다. 시스템 모니터링 관점에서 eBPF를 사용하여 특정 GPU 드라이버 함수 호출 패턴을 추적함으로써 GPU 사용량 불균형이나 비정상적인 동작을 감지할 수 있다.
*   **파일 시스템 I/O:** 대규모 학습 데이터셋을 로딩할 때 파일 시스템 I/O 성능은 병목 현상의 주요 원인이 될 수 있다. 커널은 VFS(Virtual File System) 계층을 통해 다양한 파일 시스템을 추상화하며, 페이지 캐싱을 통해 자주 접근하는 데이터를 물리 메모리에 유지하여 디스크 I/O를 줄인다. 그러나 LLM 학습과 같이 순차적이고 대규모의 데이터 읽기가 반복되는 경우, 애플리케이션은 `O_DIRECT` 플래그를 사용하여 Direct I/O를 수행함으로써 운영체제 페이지 캐시를 우회하고 디스크와 직접 데이터를 주고받는다. 이는 캐시 오버헤드를 줄이고 예측 가능한 I/O 성능을 얻는 데 기여한다. `splice` 및 `sendfile`과 같은 시스템 콜은 커널 내부에서 데이터 복사 없이 파일 디스크립터 간에 데이터를 직접 전송하여 I/O 효율을 높인다. 컨테이너 환경에서는 스토리지 드라이버(OverlayFS, AUFS 등)가 파일 시스템 격리를 제공하며, 이로 인한 성능 오버헤드 또한 고려해야 한다. eBPF는 `vfs_read()` 또는 `ext4_read_iter()`와 같은 VFS 및 파일 시스템 특정 함수를 트레이싱하여 파일 I/O 패턴, 지연 시간, 처리량을 상세하게 분석하고 I/O 병목을 정확히 식별하는 데 매우 효과적이다.

### 1.2 메모리 I/O 레벨에서의 동작 원리

LLM의 성능은 메모리 시스템의 물리적 특성 및 효율성에 크게 좌우된다.

*   **DRAM 및 HBM:** 모델 가중치와 활성화 값은 주로 GPU의 고대역폭 메모리(HBM) 또는 시스템의 DRAM(Double Data Rate Synchronous Dynamic Random-Access Memory)에 저장된다. HBM은 TSV(Through-Silicon Via) 기술을 사용하여 여러 DRAM 다이를 수직으로 쌓아 올려 GPU 패키지 내부에 통합되며, 극도로 높은 대역폭과 전력 효율을 제공하여 GPU의 병렬 연산 유닛에 데이터를 빠르게 공급한다. 반면 DRAM은 시스템 메인 메모리로 활용되며, 일반적으로 GPU HBM보다 낮은 대역폭을 가진다. 대규모 학습 데이터의 버퍼링, CPU 기반 전처리, 모델 체크포인트 저장 등에 사용된다. HBM의 대역폭과 DRAM의 용량 사이의 균형은 LLM 학습 시스템 설계에서 중요한 고려사항이다.
*   **CPU-GPU 간 통신:** 모델 학습 중 CPU와 GPU 간의 데이터 전송은 주로 PCIe(Peripheral Component Interconnect Express) 버스를 통해 이루어진다. PCIe는 직렬(serial) 인터페이스이며, 세대(Gen4, Gen5) 및 레인(x16) 수에 따라 최대 대역폭이 결정된다. Zero-copy 기법은 CPU 메모리 페이지를 GPU가 직접 접근할 수 있도록 매핑하여 CPU와 GPU 메모리 간 데이터 복사 횟수를 줄여 전송 효율을 높인다. DMA(Direct Memory Access) 엔진은 CPU의 개입 없이 메모리 간 데이터 전송을 가능하게 하여 CPU 오버헤드를 감소시킨다. 고성능 시스템에서는 NVIDIA의 NVLink와 같은 전용 고속 인터커넥트가 PCIe의 대역폭 한계를 넘어 GPU 간 또는 CPU-GPU 간 훨씬 높은 대역폭과 낮은 지연 시간을 제공하여, 멀티-GPU 분산 학습의 통신 병목을 완화한다. CXL(Compute Express Link)은 CPU와 가속기, 메모리 간 일관된 메모리 공간을 제공하는 새로운 개방형 표준으로, 향후 이종 컴퓨팅 환경에서 메모리 접근 효율을 크게 개선할 잠재력을 가진다.
*   **메모리 계층 구조 및 캐싱:** 현대 프로세서(CPU 및 GPU)는 여러 단계의 캐시(L1, L2, L3)를 사용하여 컴퓨팅 코어와 메인 메모리 간의 속도 차이를 줄인다. L1 캐시는 가장 빠르고 작으며 코어에 가깝고, L3 캐시는 가장 느리고 크며 모든 코어가 공유한다. LLM 연산 시에도 이 캐시 계층이 활용되지만, 모델 크기가 워낙 크기 때문에 전체 모델이 캐시에 상주하기 어렵고 캐시 미스율이 높아질 수 있다. 데이터 지역성(data locality)을 고려한 모델 설계 및 배치 사이즈(batch size) 조정은 캐시 효율을 높이는 중요한 알고리즘 최적화 기법이다. 캐시 일관성 프로토콜(예: MESI)은 멀티코어 환경에서 여러 캐시 간에 데이터 일관성을 유지하는 복잡한 메커니즘을 제공한다.
*   **메모리 스와핑 및 페이징:** 모델 크기가 가용한 물리 메모리(특히 GPU 메모리)를 초과할 경우, 운영체제는 `kswapd` 데몬을 통해 사용 빈도가 낮은 메모리 페이지를 디스크의 스왑 공간으로 옮겨 물리 메모리를 확보한다. 이는 시스템 콜 레벨에서 I/O를 유발하여 성능 저하로 직결된다. 이를 회피하기 위해, 애플리케이션 레벨에서는 `madvise()` 시스템 콜을 사용하여 커널에게 메모리 사용 패턴에 대한 힌트(예: `MADV_DONTNEED`로 즉시 해제될 페이지 지정)를 제공할 수 있다. 모델 분할(model parallelism, 예: Megatron-LM), 옵티마이저 스테이트 오프로딩(optimizer state offloading, 예: DeepSpeed ZeRO-Offload가 옵티마이저 상태를 CPU RAM 또는 NVMe SSD로 이동) 등의 기법을 사용하여 GPU 메모리 사용량을 최적화해야 한다. `mincore()` 시스템 콜은 특정 가상 메모리 페이지가 물리 메모리에 상주하는지 여부를 확인할 수 있어 메모리 사용 현황을 진단하는 데 활용될 수 있다.

### 1.3 패킷 처리 레벨에서의 동작 원리

분산 학습 및 추론 환경에서 LLM은 네트워크를 통해 노드 간 대량의 데이터를 교환하며, 패킷 처리의 효율성은 전체 시스템 성능에 결정적인 영향을 미친다.

*   **네트워크 인터페이스 카드 (NIC):** NIC는 물리 계층(비트 전송)과 데이터 링크 계층(프레임 처리)에서 패킷을 처리하는 하드웨어 장치다. 이더넷 프레임을 생성/파싱하고, MAC 주소 기반의 스위칭 기능을 제공한다. 최신 NIC는 체크섬 오프로딩(checksum offloading), TSO(TCP Segmentation Offload), LRO(Large Receive Offload)와 같은 하드웨어 오프로딩 기능을 제공하여 CPU의 패킷 처리 부담을 줄인다. 또한, RSS(Receive Side Scaling)는 수신 패킷을 여러 CPU 코어에 분배하여 처리 효율을 높이고, SR-IOV(Single Root I/O Virtualization)는 가상 머신이나 컨테이너가 NIC의 물리적 자원에 직접 접근(Direct Pass-through)할 수 있도록 하여 가상화 환경에서의 네트워크 오버헤드를 최소화한다. eBPF는 XDP(eXpress Data Path) 모드에서 NIC 드라이버 레벨에 로드되어 인커밍 패킷을 커널 네트워크 스택 진입 전에 필터링, 드롭, 리다이렉트할 수 있어 DDos 방어나 고성능 로드밸런싱 등 네트워크 패킷 처리 성능을 대폭 향상시킨다.
*   **TCP/IP 스택:** 분산 LLM 학습은 주로 TCP/IP 프로토콜 스택을 통해 노드 간 통신한다. TCP는 `socket()` 시스템 콜로 생성되며, 3-way handshake를 통해 연결을 설정하고, 순서 번호, 확인 응답, 윈도우 기반 흐름 제어 및 혼잡 제어(예: CUBIC, BBR 알고리즘) 메커니즘을 사용하여 신뢰성 있는 데이터 전송을 보장한다. IP는 `sendto()`/`recvfrom()`과 같은 시스템 콜을 통해 사용되며, 비연결형 프로토콜로, 패킷의 라우팅을 담당한다. LLM 분산 학습에서는 그라디언트 교환, 모델 파라미터 동기화 등 대량의 데이터가 오가므로, 네트워크 대역폭, 지연 시간, 그리고 스택 내에서의 효율적인 처리(예: `sendfile`이나 `splice`를 활용한 Zero-copy socket API)가 중요하다. 컨테이너 환경에서는 네트워크 네임스페이스(Network Namespace)를 통해 독립적인 네트워크 스택(인터페이스, 라우팅 테이블, 포트 등)을 제공하여 네트워크 격리를 구현한다. eBPF는 `tcp_sendmsg()` 또는 `ip_rcv()`와 같은 커널 네트워크 스택의 함수 호출을 트레이싱하여 TCP 혼잡 제어 상태, RTT(Round Trip Time), 패킷 드롭률 등 상세한 네트워크 성능 지표를 실시간으로 모니터링하고 분석하는 데 활용될 수 있다.
*   **RDMA (Remote Direct Memory Access):** 고성능 분산 학습 클러스터에서는 RDMA(RoCEv2, InfiniBand 등) 기술을 활용하여 CPU의 개입 없이 원격 노드의 메모리에 직접 접근한다. 이는 `verbs` API를 통해 이루어지며, 네트워크 스택 오버헤드를 대폭 줄이고, 극도로 낮은 지연 시간(수 마이크로초)과 높은 대역폭(수백 Gbps)을 제공하여 LLM의 분산 학습 효율을 극대화한다. RDMA는 GPU Direct RDMA와 결합되어 GPU 메모리에서 직접 데이터를 전송하는 것도 가능하게 한다. 이 기술은 특히 All-reduce와 같은 집단 통신(collective communication) 연산에서 통신 오버헤드를 크게 줄여준다. RDMA를 지원하는 네트워크 하드웨어(HCA: Host Channel Adapter)와 드라이버가 필요하며, 컨테이너 환경에서는 `--device` 옵션을 통해 RDMA 디바이스를 컨테이너 내부로 노출해야 한다.
*   **네트워크 토폴로지:** 클러스터 내부의 네트워크 토폴로지는 통신 성능에 결정적인 영향을 미친다. 스파인-리프(Spine-Leaf) 또는 클로스(Clos)와 같은 고대역폭, 저지연 토폴로지는 노드 간 통신 병목 현상을 줄이는 데 필수적이다. 이러한 토폴로지는 모든 서버가 동일한 수의 스위치 홉(hop)을 통해 서로 통신할 수 있도록 설계되어, 예측 가능한 대역폭과 지연 시간을 제공한다. 옵티마이저(Optimizer) 및 데이터 병렬 처리(Data Parallelism) 방식에 따라 네트워크 요구사항이 달라지므로, 적절한 토폴로지 설계와 스위치, 라우터 구성이 필요하다. 특히, LLM의 학습 과정에서 발생하는 빈번한 그라디언트 동기화는 네트워크 대역폭을 크게 소모하므로, 대규모 병렬 학습 시 네트워크 토폴로지 설계와 케이블링은 중요한 알고리즘 최적화의 한 부분으로 간주될 수 있다.

## 데이터의 자율성과 통제: 커널 엔지니어의 시각으로 본 데이터 아키텍처의 미래

데이터 아키텍처는 보통 서비스 개발 상위 레벨의 주제로 다뤄집니다. 하지만 저는 컨테이너 보안을 연구하며 Linux 커널과 시스템 콜이라는 가장 낮은 레벨에서 '누가, 언제, 어떻게 시스템 자원에 접근하는가'를 관찰하고 통제하는 경험을 했습니다. 데이터 패브릭, 메시, 거버넌스 역시 '누가, 언제, 어떻게 데이터 자원에 접근하는가'를 다루는 문제이며, 그 본질은 같다고 생각합니다. 시스템의 가장 낮은 곳부터 이해하는 저의 경험을 통해 데이터 아키텍처를 '보안'과 '통제', '효율'이라는 새로운 관점에서 해석하고, 저의 강점인 '근본 원인 해결' 역량을 어필하기 위해 이 주제를 선정했습니다. 이는 제가 시스템 아키텍처로 지식을 확장하고자 하는 의지를 보여주는 최고의 주제라고 판단했습니다.

(서론 - 30초)
혹시 '데이터 사일로'라는 말 들어보셨습니까? 기업 내 데이터가 부서별로 고립되어 전사적인 활용이 어려운 문제를 뜻합니다. 특히 요즘처럼 AI 기술이 중요해진 시대에, 이런 고립은 기업의 경쟁력을 심각하게 저해합니다. AI 모델의 성능은 데이터의 품질과 양에 의해 결정되기 때문입니다.

이 문제를 해결하기 위해 데이터 패브릭, 데이터 메시, 그리고 데이터 거버넌스라는 세 가지 개념이 주목받고 있습니다. 오늘 저는 이 세 가지 개념을 소개하고, 특히 시스템의 가장 근본부터 고민해 온 저의 경험을 바탕으로 이 주제를 어떻게 바라보는지 말씀드리고자 합니다.

(본론 - 2분)
먼저 **데이터 거버넌스**입니다. 저는 이것을 '데이터 세계의 헌법'이라고 정의하고 싶습니다. 데이터가 언제, 어디서, 누구에 의해 생성되고 사용되며 폐기되는지, 그 전 과정의 규칙과 책임을 정하는 것이 바로 데이터 거버넌스입니다. 단순히 데이터를 통제하는 것이 아니라, 모든 사람이 믿고 쓸 수 있는 고품질 데이터를 '활성화'하기 위한 필수 기반입니다.

이 거버넌스라는 기반 위에서, 두 가지 새로운 데이터 아키텍처 접근법이 등장합니다. 바로 **데이터 패브릭**과 **데이터 메시**입니다.

첫째, **데이터 패브릭**은 기술 중심적인 접근입니다. 여러 곳에 흩어진 데이터 소스를 물리적으로 옮기지 않고, 지능화된 메타데이터를 이용해 가상으로 연결하는 '그물망(Fabric)'을 만드는 것입니다. AI 기술을 통해 데이터 통합, 관리, 전달 과정을 자동화하여 사용자가 필요할 때 즉시 데이터를 쓸 수 있게 해줍니다.

둘째, **데이터 메시**는 조직 중심적인 접근입니다. 이는 기술 이전에 철학의 전환을 요구합니다. 중앙 데이터 팀이 모든 데이터를 관리하는 대신, 각 비즈니스 도메인 팀이 자신들의 데이터를 직접 소유하고 '제품(Data as a Product)'처럼 책임지고 제공하는 방식입니다. 중앙 팀은 데이터 플랫폼만 제공하고, 각 팀은 자율성을 갖고 민첩하게 움직입니다.

정리하면, 패브릭은 '기술적 통합과 자동화', 메시는 '조직적 분산과 자율성'에 중점을 둡니다. 두 가지는 경쟁 관계가 아니라, 데이터 거버넌스라는 큰 틀 안에서 상호 보완적으로 사용될 수 있습니다.

**바로 이 지점에서 저의 경험을 연결해 말씀드리고 싶습니다.**
저는 컨테이너 보안을 연구하며, 애플리케이션이 운영체제 자원을 사용하기 위해 반드시 거쳐야 하는 길목인 '시스템 콜'을 동적으로 관찰했습니다. 수많은 시스템 콜의 패턴을 분석해 정상 프로필을 만들고, 여기서 벗어나는 이상 행위를 탐지하는 모델을 개발했습니다.

저는 데이터 세계의 'API 호출'이나 'DB 쿼리'가 바로 이 시스템 콜과 같다고 생각합니다. 데이터에 접근하기 위한 유일한 통로이기 때문입니다. 제가 시스템 콜을 관찰해 보안 문제를 해결했듯이, 데이터 접근 요청을 실시간으로 관찰하고 분석하면, 데이터 유출 같은 보안 위협이나 데이터 오남용을 자동으로 탐지하고 차단할 수 있습니다. 이것이 바로 데이터 거버넌스를 자동화하고, 데이터 패브릭과 메시를 더 안전하고 효율적으로 만드는 핵심 기술이 될 것이라 확신합니다.

(결론 - 30초)
결론적으로, 데이터 패브릭의 자동화된 기술, 그리고 데이터 메시의 분산된 자율성은, 데이터 거버넌스라는 일관된 원칙 하에 통합될 때 비로소 진정한 가치를 발휘합니다.

저는 리눅스 커널 수준의 동작 원리를 이해하고 있으며, 이를 통해 시스템의 보안과 안정성을 고민해 본 경험이 있습니다. SSAFY의 기본 과정에서 코딩테스트 역량을 다져 B형 자격증을 취득하고, 심화 과정의 프로젝트를 통해 다양한 기술 스택을 갖춘 동료들과 협업하며 풀스택 서비스 구현 역량을 기르겠습니다. 그렇게 시스템의 근본과 서비스 아키텍처를 모두 이해하는 '융합형 개발자'로 성장하여, 오늘 말씀드린 것처럼 보안과 효율이 보장된 데이터 플랫폼을 설계하고 구현하는 데 기여하고 싶습니다.

이상으로 발표를 마치겠습니다. 경청해주셔서 감사합니다.

### 5. 예상 꼬리질문 5개 + 답변 방향 (기술적 깊이가 드러나게, 각 2~3문장)
1.  **Q. 데이터 패브릭과 데이터 메시 중 한 가지만 선택해야 한다면, 어떤 기준을 고려하겠습니까?**
    *   **A.** 조직의 성숙도와 문화를 가장 먼저 고려하겠습니다. 기술적 통합이 시급하고 중앙 거버넌스 역량이 충분하다면 데이터 패브릭으로 빠른 효과를 볼 수 있습니다. 반면, 이미 도메인별 전문성이 높고 빠른 의사결정이 중요한 대규모 조직이라면, 점진적으로 데이터 메시를 도입해 조직적 변화를 유도하는 것이 장기적으로 더 효과적일 것입니다.
2.  **Q. 본인의 시스템 콜 이상탐지 경험을 데이터 거버넌스에 구체적으로 어떻게 적용할 수 있을지, 기술적인 예를 들어 설명해주세요.**
    *   **A.** 예를 들어, 리눅스 커널의 eBPF(extended Berkeley Packet Filter) 기술을 활용할 수 있습니다. eBPF를 사용하면 커널 코드 수정 없이 데이터베이스 드라이버나 네트워크 스택 레벨에서 발생하는 SQL 쿼리나 API 호출을 실시간으로 가로채고 분석할 수 있습니다. 저는 이 원리를 이용해 정상적인 데이터 접근 패턴(예: 특정 서비스는 User 테이블의 특정 컬럼만 조회)을 프로파일링하고, 여기서 벗어나는 비정상 행위(예: 갑작스러운 대량 데이터 export 시도)를 실시간으로 탐지하여 알리거나 차단하는 '데이터 이상행위 탐지 시스템'을 설계하고 구현해보고 싶습니다.
3.  **Q. 데이터 메시에서 '데이터를 제품으로 다룬다(Data as a Product)'는 것의 구체적인 의미는 무엇입니까?**
    *   **A.** 단순히 데이터를 제공하는 것을 넘어, 소비자가 이 데이터를 쉽게 발견(Discoverable)하고, 이해(Understandable)하며, 신뢰(Trustworthy)하고, 주소 지정(Addressable)할 수 있는 형태로 가공하여 제공한다는 의미입니다. 이는 명확한 API 엔드포인트, 최신화된 문서, 데이터 품질 지표(SLA/SLO), 명확한 소유자 정보 등을 데이터와 함께 패키징하여 제공하는 것을 포함합니다.
4.  **Q. 데이터 거버넌스가 강화되면 현업 부서의 데이터 활용이 위축될 수 있다는 우려가 있습니다. 어떻게 해결해야 할까요?**
    *   **A.** '중앙 집중적 통제'가 아닌 '연합 거버넌스(Federated Governance)' 모델 도입이 해결책이 될 수 있습니다. 이는 데이터 보안, 개인정보보호와 같은 전사적 표준은 중앙에서 정하되, 각 도메인 데이터의 품질이나 표준 모델 정의 등은 도메인 전문가들이 자율적으로 결정하고 책임지게 하는 방식입니다. 즉, 중앙에서는 '어떻게'가 아닌 '무엇을' 지켜야 하는지에 대한 가드레일만 제공하여 자율성은 높이고 리스크는 줄이는 접근입니다.
5.  **Q. 이 주제에 대해 학습하면서 기술적으로 가장 흥미로웠거나 어려웠던 부분은 무엇이었습니까?**
    *   **A.** 기술적으로는 데이터 가상화(Data Virtualization) 기술과 지능형 메타데이터(Active Metadata)를 활용해 데이터 패브릭을 구현하는 원리가 가장 흥미로웠습니다. 반면, 가장 어려웠던 부분은 데이터 메시가 요구하는 조직 문화의 변화, 즉 '사회기술적(Sociotechnical)' 측면을 이해하는 것이었습니다. 최고의 기술도 결국 사람이 쓰는 것이기에, 기술 도입이 조직 구조와 개개인의 역할을 어떻게 바꾸는지 이해하고 설득하는 과정의 중요성을 깨달았고, 이는 제가 SSAFY에서 동료들과 협업하며 길러야 할 핵심 역량이라고 생각합니다.

### 6. 지원자 경험 연결 (컨테이너 보안·syscall 동적 관측·Linux 커널·이상탐지 경험을 자연스럽게 엮는 멘트)
제가 컨테이너의 구조적 보안 문제를 해결하기 위해, 수많은 시스템 콜을 동적으로 관찰하며 정상과 비정상 행위를 구분하는 이상탐지 모델을 만들었던 경험이 있습니다. 이 과정에서 저는 애플리케이션의 모든 행동이 결국 커널 자원을 요청하는 시스템 콜로 귀결되며, 이 길목을 지키는 것이 보안의 핵심임을 깨달았습니다.

데이터 아키텍처를 공부하며 저는 이 경험을 떠올렸습니다. 데이터베이스를 향한 수많은 쿼리, 서비스 간의 API 호출들이 마치 시스템 콜처럼 보였습니다. 데이터라는 핵심 자원에 접근하기 위한 길목이기 때문입니다. 따라서 제가 가졌던 '동적 관찰을 통한 이상탐지'라는 경험은, 복잡한 데이터 메시나 패브릭 환경에서 데이터의 흐름을 투명하게 관찰하고, 데이터 유출이나 오남용 같은 위협을 실시간으로 탐지하는 자동화된 데이터 거버넌스 시스템을 구축하는 데 매우 중요한 밑거름이 될 것이라고 확신합니다.

### 7. 발표 팁 / 흔한 함정 (이 주제 특유의 주의점)
*   **발표 팁:**
    *   세 가지 개념의 '정의'를 명확하고 쉽게 전달하는 것이 가장 중요합니다. (거버넌스=헌법, 패브릭=기술적 통합망, 메시=조직적 자율성)
    *   자신감 있는 태도로 '커널 엔지니어의 시각'이라는 차별화 포인트를 초반부터 명확히 하세요. 이는 다른 지원자와의 가장 큰 차별점이 될 것입니다.
    *   본인의 경험을 이야기할 때, 기술 용어(시스템 콜, 이상탐지)를 간단히 설명하며 청중의 이해를 돕는 배려를 보여주면 좋습니다.
*   **흔한 함정:**
    *   **개념 나열의 함정:** 세 개념을 각각 독립적으로 설명하는 데 그치면 안 됩니다. '거버넌스'를 기반으로, '패브릭'과 '메시'가 어떻게 문제를 해결하는지, 그리고 둘의 관계는 무엇인지 '연결'해서 설명해야 합니다.
    *   **기술 과시의 함정:** 특정 솔루션(예: dbt, Amundsen)이나 너무 깊은 기술 세부사항에 매몰되지 마세요. 이 발표는 기술 지식의 깊이보다, 아키텍처의 철학과 원칙을 이해하고 그것을 자신의 경험과 어떻게 연결하는지를 보여주는 것이 핵심입니다.
    *   **억지 연결의 함정:** 지원자 경험을 억지로 끼워 넣는다는 느낌을 주지 않도록 주의해야 합니다. '시스템 거버넌스'와 '데이터 거버넌스'의 원리가 근본적으로 '자원에 대한 접근을 관찰하고 제어한다'는 점에서 동일하다는 점을 논리적이고 설득력 있게 연결하는 것이 관건입니다.

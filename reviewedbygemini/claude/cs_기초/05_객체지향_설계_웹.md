## 0. 문서 요지 (3줄 이내)
이 문서는 SSAFY PT 면접 대비를 위해 객체지향, 소프트웨어 설계 원칙 및 패턴, 웹 기술 기초 개념을 핵심 위주로 정리한 자료입니다. 각 주제별 정의와 특징, 비교, 그리고 예상 질문 및 답변 포인트를 구조화하여 실전 면접에 활용할 수 있도록 구성되었습니다.

## 2. 최신성 점검 (2026년 기준 시점 어긋남, 오래된 수치·동향, 보강할 최신 사건)
*   **MSA 전환 전략 및 운영 환경**: 마틴 파울러의 "Monolith First" (2015) 원칙은 여전히 유효하지만, 2026년에는 MSA 도입과 전환 전략에 있어 도메인 주도 설계(DDD), 클라우드 네이티브(Cloud Native) 아키텍처, 서버리스(Serverless) 컴퓨팅, 서비스 메시(Service Mesh)와 같은 개념이 초기 설계 단계부터 중요하게 고려됩니다. 문서는 이러한 최신 동향과 이를 가능하게 하는 기술 스택(예: 쿠버네티스, 헬름)에 대한 언급이 부족하여 MSA 논의의 깊이를 더하지 못합니다.
*   **웹 인증/인가**: 세션, JWT, OAuth 2.0은 핵심적인 내용이나, 2026년에는 패스워드리스 인증의 중요성이 부각되며 FIDO2, WebAuthn과 같은 최신 인증 표준들이 폭넓게 적용되고 있습니다. 또한, API 보안의 강화 측면에서 OAuth 2.0의 확장인 DPoP(Demonstrating Proof-of-Possession)과 같은 메커니즘도 고려됩니다. 이러한 최신 흐름에 대한 언급이 없어 웹 보안 전반에 대한 최신 지식으로 보강이 필요합니다.
*   **HTTP 캐싱**: `Cache-Control`과 `ETag`는 여전히 중요하지만, CDN(Content Delivery Network)의 활용이 일반화되면서 캐싱 전략이 더욱 고도화되었습니다. CDN을 통한 엣지 캐싱, 캐시 무효화 전략 등 분산 환경에서의 캐싱 전략에 대한 내용이 보강되면 더욱 풍부한 최신성을 확보할 수 있습니다.

## 3. 누락·보완 필요 (이 주제에서 빠진 핵심 개념·쟁점·수치)
*   **디자인 패턴**: 싱글톤, 팩토리, 옵저버, 전략 패턴 외에, 실무에서 자주 사용되는 프록시, 데코레이터, 커맨드, 템플릿 메서드와 같은 다른 핵심 디자인 패턴에 대한 소개가 부족합니다. 각 패턴의 목적과 함께 실제 적용 사례를 추가하여 깊이를 더할 수 있습니다.
*   **객체지향 설계 원칙 확장**: SOLID 원칙은 잘 다루고 있으나, "불필요한 기능은 만들지 말라(YAGNI)", "간단하게 유지하라(KISS)", "반복하지 마라(DRY)"와 같은 보편적인 소프트웨어 개발 원칙에 대한 언급이 없어 아쉽습니다.
*   **데이터 저장 기술**: 웹 서비스 아키텍처에서 데이터베이스는 핵심 요소임에도 불구하고 RDB(관계형 데이터베이스) 외에 NoSQL(Document, Key-Value, Graph, Column-family 등) 데이터베이스의 종류와 각 특징, MSA 환경에서의 데이터 정합성 유지 전략(예: Saga 패턴)에 대한 내용이 전무합니다.
*   **비동기/동시성 모델**: 프로세스와 스레드에 대한 설명은 있으나, 현대 웹 서비스에서 중요한 비동기 처리 모델인 이벤트 루프(Event Loop) 기반의 Node.js나 Python의 `async/await`과 같은 프로그래밍 모델, 또는 액터(Actor) 모델(예: Akka)에 대한 언급이 없어 아쉽습니다.
*   **테스트 및 품질**: 소프트웨어 설계 및 개발에서 필수적인 테스트(단위 테스트, 통합 테스트, E2E 테스트)의 중요성과 TDD(테스트 주도 개발), BDD(행위 주도 개발)와 같은 개발 방법론에 대한 내용이 누락되어 있습니다.
*   **API 설계**: REST API에 대한 직접적인 언급은 없으나, 웹 기초에서 다루는 내용들이 대부분 REST 기반입니다. RESTful API의 원칙, GraphQL과 같은 대체 API 기술, API Gateway의 역할 등 API 설계와 관련된 내용이 보강되면 좋습니다.

## 4. 추가 조사 주제 제안 (이 자료를 보충할 새 조사 주제 5개)
*   `cloud-native-architecture`: 클라우드 환경에 최적화된 MSA 구축 및 운영 방법론으로, 현대 소프트웨어 아키텍처의 핵심 축을 이룸.
*   `serverless-computing-faas`: 서버 관리 없이 코드를 실행하는 방식으로, 효율적인 자원 사용과 빠른 배포를 가능하게 하는 최신 웹 서비스 운영 패러다임.
*   `api-gateway-service-mesh`: 마이크로서비스 간 통신 관리(트래픽 제어, 보안, 관찰 가능성 등)의 복잡성을 해결하고 시스템 안정성을 높이는 핵심 기술.
*   `database-for-microservices`: MSA 환경에서 데이터 일관성과 독립성을 유지하기 위한 다양한 데이터베이스 전략(polyglot persistence, saga pattern 등)과 NoSQL DB 종류.
*   `webauthn-fido2-passwordless`: 비밀번호 없는 인증 시대를 이끄는 웹 표준 기술로, 2026년 웹 보안 및 사용자 경험 향상에 필수적.

## 5. PT 발표 활용도 (강점 / 약점 / 발표 시 주의점)
**강점**:
*   핵심 CS 및 웹 기초 개념을 면접 질문과 답변 포인트 형태로 명료하게 정리하여 실전 면접 준비에 매우 효과적입니다.
*   객체지향, 소프트웨어 설계, 웹 기술 전반을 아우르는 넓은 범위를 다루어 기본적인 지식 검증에 충분합니다.
*   마틴 파울러의 "Monolith First"와 같은 권위 있는 주장을 인용하여 논리적 근거를 제시하고 있습니다.
*   개념 비교(오버로딩 vs 오버라이딩, 추상클래스 vs 인터페이스, 상속 vs 합성, 세션 vs JWT 등)가 잘 되어 있어 명확한 이해를 돕습니다.

**약점**:
*   2026년 현재의 기술 트렌드(클라우드 네이티브, 서버리스, 서비스 메시, AI/MLOps, WebAuthn 등)에 대한 내용이 부족하여 최신 기술 면접에 취약할 수 있습니다.
*   일부 개념(예: 디자인 패턴의 깊이 있는 활용 사례, MSA 운영의 실제적 어려움과 해결책)에 대한 설명이 다소 피상적일 수 있습니다.
*   웹 보안의 경우 인증/인가에 국한되어 있으며, XSS, CSRF, SQL 인젝션 등 웹 취약점 및 대응 방안에 대한 언급이 없어 웹 보안 전반에 대한 이해도가 부족해 보일 수 있습니다.
*   특정 언어(Java)에 특화된 설명(예: 인터페이스)이 있어, 다른 언어 기반의 면접에서는 추가적인 준비가 필요할 수 있습니다.

**발표 시 주의점**:
*   2026년 최신 IT 트렌드(특히 클라우드, AI, 보안 분야)와 문서 내 개념들을 어떻게 연결하여 설명할지 미리 준비해야 합니다.
*   면접관이 특정 개념의 깊이 있는 이해나 실무 적용 경험을 물을 경우를 대비하여, 각 개념에 대한 본인의 경험이나 구체적인 예시를 추가적으로 정리해두어야 합니다.
*   "모놀리식 먼저"와 같은 원칙을 언급할 때는 단순히 인용하는 것을 넘어, 본인의 관점과 최신 MSA 도입/전환 전략에 대한 이해를 함께 보여주는 것이 중요합니다.
*   웹 보안 질문에 대비하여 기본적인 웹 취약점과 방어 전략에 대한 추가 학습이 필요합니다.
*   문서에 언급되지 않은 핵심 개념(예: NoSQL, GraphQL, 메시지 큐)에 대한 질문이 나올 수 있으므로, 해당 분야에 대한 최소한의 지식은 갖추는 것이 좋습니다.

## 6. 종합 평가 (정확성·완성도·발표적합도 각각 상/중/하 + 한 줄 총평)
*   **정확성**: 상
*   **완성도**: 중
*   **발표적합도**: 중

**총평**: SSAFY PT 면접 대비를 위한 CS 기초 및 웹 기술 정리 자료로서 매우 충실하며 기본적인 지식 습득에 용이하지만, 2026년 최신 기술 동향과 실무적 깊이를 보강하여 면접 경쟁력을 더욱 높일 필요가 있습니다.

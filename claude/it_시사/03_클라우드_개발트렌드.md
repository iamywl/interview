# 클라우드 / 소프트웨어 개발 트렌드 (2021–2026)

> SSAFY 취업 면접 준비용 IT 뉴스 리서치. 사실·날짜 중심으로 정리했으며, 2025–2026년 최신 동향을 반영했다.

---

## 1. 클라우드 3사(AWS·Azure·GCP) 경쟁과 점유율

- **2021~2024 — AWS 1위 유지, 점유율 점진 하락** — AWS는 2024년 초 31% 수준에서 점차 내려오며 1위를 지키되 격차가 좁혀졌다. Azure는 기업용 시장(Office 365, AD 연계)과 OpenAI 제휴를 무기로 추격.
- **2025년 1분기(Synergy Research 기준) AWS 29% / Azure 22% / Google Cloud 12%** — 3사 합산이 전체 기업 클라우드 지출의 약 63%. GCP는 11%→12%로 꾸준히 성장.
- **2025~2026 — 시장 자체가 AI 수요로 급팽창** — 2026년 1분기 글로벌 클라우드 인프라 지출은 전년 대비 약 35% 증가(분기 약 1,290억 달러). 성장률은 GCP가 가장 빠르고, Azure가 뒤를, AWS가 절대 규모 1위 유지.
- **의미** — 점유율 수치는 출처(Synergy, Canalys 등)별 ±2~3%p 차이가 난다. 면접에서는 정확한 숫자보다 **"AWS 1위·Azure 추격·GCP 최고 성장률, AI가 시장 전체를 키운다"**는 구조로 말하는 것이 안전하다.

---

## 2. 쿠버네티스 / 컨테이너 / 클라우드 네이티브

- **2021~2023 — 쿠버네티스가 컨테이너 오케스트레이션 사실상 표준화** — Docker 단독에서 K8s 기반 운영으로 전환. CNCF 생태계(Prometheus, Envoy, Helm 등) 성숙.
- **2025년(CNCF 연례 조사, 2026.01 발표) — 컨테이너 사용 조직의 82%가 프로덕션에서 쿠버네티스 운영** — 조직의 93%가 K8s 사용·파일럿·평가 중. 쿠버네티스가 "AI의 운영체제(OS)"로 자리매김.
- **2025 — 생성형 AI 워크로드를 K8s로 운영** — 생성형 AI 호스팅 조직의 66%가 추론(inference) 워크로드 일부/전부를 K8s로 관리.
- **의미** — 쿠버네티스는 "배우면 좋은 기술"에서 "기본 인프라"로 굳어졌다. AI 시대에도 모델 서빙·GPU 스케줄링의 표준 플랫폼.

---

## 3. 서버리스(Serverless)

- **2021~2024 — AWS Lambda, Cloud Run, Azure Functions 확산** — 이벤트 기반·비용 효율(scale-to-zero) 장점으로 채택 증가.
- **2025 — 채택이 양분됨** — 일부 조직은 확대하나 일부는 **비용 예측 어려움·복잡성·콜드스타트** 문제로 사용 축소. 폭발적 성장이 아니라 "선별적 사용" 단계.
- **의미** — 트래픽이 불규칙하거나 운영 부담을 줄이려는 워크로드에 적합하다는 현실적 인식이 정착.

---

## 4. DevOps / 플랫폼 엔지니어링(Platform Engineering)

- **2021~2023 — DevOps 보편화, CI/CD·IaC·GitOps 정착** — Terraform, ArgoCD, GitHub Actions 등.
- **2024~2025 — "플랫폼 엔지니어링"이 핵심 트렌드로 부상** — 모든 개발자에게 DevOps 부담을 지우는 대신, **내부 개발자 플랫폼(IDP)**과 "골든 패스(golden path)"로 개발자 경험(DevEx)을 높이는 방향.
- **의미** — "DevOps의 다음 단계"를 물으면 플랫폼 엔지니어링(셀프서비스 플랫폼·개발자 생산성)을 언급할 수 있다.

---

## 5. AI 코딩 도구 — GitHub Copilot, Cursor, Claude Code와 "바이브 코딩"

가장 변화가 빠른 영역이다.

- **2021~2022 — GitHub Copilot 출시(2021 프리뷰, 2022 정식)** — OpenAI Codex 기반 자동완성으로 AI 페어 프로그래밍 시대 개막.
- **2023~2024 — 자동완성에서 "에이전트"로** — 다중 파일을 다루는 에이전트형 도구 등장. Cursor(AI 네이티브 IDE) 급부상.
- **2025 — "바이브 코딩(vibe coding)" 용어 확산** — 자연어로 의도만 전달하면 AI가 코드를 생성·수정. Cursor 사용자 2025년 초 50만 → 2026년 5월 400만 명+, 포춘 500 약 2/3 사용.
- **2025~2026 — 시장 재편, Copilot 독점 붕괴** — JetBrains 2026 조사에서 Copilot 29% / Cursor 18% / Claude Code 18%로 3강 구도. Claude Code는 2025.04 3% → 2026.01 18%로 약 6배 성장.
- **2026 — AI 생성 코드 비중 급증** — 전 세계 개발자의 약 90%가 업무에 AI 도구를 정기 사용.
- **의미** — AI 코딩 도구는 "선택"이 아니라 "기본 역량". 면접에서는 도구 자랑보다 **"AI가 생성한 코드를 검증·리뷰·책임지는 능력"**을 강조하는 것이 효과적이다.

> 주의: 점유율 수치는 조사 기관(Stack Overflow vs JetBrains)별 정의·표본이 달라 편차가 크다. 추세("Copilot 독점 → 다극화")로 말하는 것이 안전하다.

## 6. 오픈소스 생태계 — 라이선스 변경과 포크(fork)

벤더가 하이퍼스케일러의 무임승차를 막으려 라이선스를 조이고, 커뮤니티가 포크로 대응하는 패턴이 반복됐다.

- **2021 — Elastic, Elasticsearch를 SSPL로 변경 → AWS가 OpenSearch로 포크** (2024.08 Elastic이 AGPL 추가로 오픈소스 옵션 복원).
- **2023.08 — HashiCorp, Terraform 등을 MPL→BSL 1.1(source-available)로 변경** — 커뮤니티가 포크 → Linux Foundation 산하 **OpenTofu**(2024.01 안정 버전).
- **2024.03 — Redis, BSD→RSALv2+SSPL 이중 라이선스 변경** — 기여자들이 마지막 BSD 버전을 포크해 Linux Foundation 산하 **Valkey** 출범.
- **의미** — "오픈소스의 지속가능한 수익 모델"과 "커뮤니티 신뢰" 사이의 긴장이 핵심 이슈. 포크가 중립 재단(Linux Foundation)으로 가는 것이 안전판 역할.

## 7. 주요 언어 / 프레임워크 트렌드

- **JavaScript / TypeScript** — JS는 2025년에도 가장 많이 쓰이는 언어(약 66%). TS는 타입 안정성으로 프론트·백엔드 표준.
- **Python — AI/데이터로 급성장** — 2024→2025 사용률 7%p 상승. AI·데이터·백엔드 사실상 기본 언어.
- **Rust — "가장 사랑받는 언어"** — 2025 Stack Overflow admired 1위(약 72%). 메모리 안전성·성능으로 시스템·인프라 채택 확대.
- **Go — 클라우드 네이티브의 언어** — K8s·Docker·Terraform이 Go로 작성됨. 백엔드·CLI·마이크로서비스 강세.
- **React** — 프론트엔드 라이브러리 표준 지위 유지.
- **의미** — "현재 가장 많이 쓰는 언어(JS·Python)"와 "배우고 싶어하는 언어(Rust·Go·TS)"가 다르다는 점이 포인트.

## 8. 대규모 장애(Outage) 사례 — "단일 의존성의 위험"

면접에서 가용성·복원력(resilience)을 말할 때 활용도가 높다.

- **2021.10.04 — 페이스북(Meta) 약 6~7시간 글로벌 다운** — 백본 점검 중 잘못된 명령으로 BGP 경로 철회→DNS 도달 불가. Instagram·WhatsApp 동시 마비.
- **2022.10.15 — SK C&C 판교 데이터센터 화재 → 카카오 먹통** — 전기실 배터리 화재로 전원 차단. 카카오톡·페이·T·다음 마비. 데이터센터 이중화·재해복구(DR) 의무화 논의 촉발. (상세는 05번 문서)
- **2024.07.19 — 크라우드스트라이크(CrowdStrike) 글로벌 IT 대란** — 보안 SW의 잘못된 커널 설정 업데이트로 윈도우 약 850만 대 블루스크린(BSOD). 항공편 5,000여 편 취소. "역사상 최대 IT 장애".
- **2025.10.19~20 — AWS us-east-1 약 15시간 장애** — DynamoDB 자동 DNS 관리의 경쟁 상태(race condition)가 70개+ 서비스로 연쇄. 글로벌 서비스가 us-east-1에 의존해 타 리전까지 영향.
- **2025.10.29 — Azure 장애** — Azure Front Door 설정 변경 오류.
- **2025.11.18 — Cloudflare 글로벌 장애** — DB 권한 변경으로 봇 관리 설정 파일이 한도 초과→핵심 프록시 패닉, HTTP 5xx 대량 발생. 사이버 공격 아닌 내부 설정 오류.
- **의미** — 2024~2025 대형 장애의 공통 교훈: **소수 핵심 인프라(AWS us-east-1, Cloudflare, CrowdStrike)에 인터넷 전체가 과도하게 의존**. 멀티리전·멀티클라우드, 점진적 배포(canary), 변경 검증, 롤백 체계의 중요성.

## 9. SaaS / 구독 모델

- **2021~2024 — SaaS·구독 모델 보편화** — 패키지 판매에서 월/연 구독(ARR 중심)으로 전환.
- **2025~2026 — AI 기능을 구독에 결합, 가격 재편** — 가치 측정 단위가 "시트(seat)"에서 "사용량·성과(usage/outcome)"로 이동. 비용 예측·FinOps가 중요한 운영 과제.

## 10. 한국 IT 서비스 동향 (네이버·카카오 등)

- **2022.10 — 카카오 먹통 사태** — 데이터센터 이중화·DR 경각심. 카카오는 향후 5년 약 3배 투자 확대·자체 데이터센터(안산) 구축.
- **2023~2025 — 네이버 HyperCLOVA X(한국어 LLM)** — 2025.04 오픈소스 경량 모델 **HyperCLOVA X SEED**(0.5B/1.5B/3B) 공개. 네이버클라우드가 공공·금융에서 소버린 클라우드(데이터 주권)로 차별화.
- **2024.10 — 카카오, 'if kakao AI 2024'에서 AI 메이트 "카나나(Kanana)" 공개**.
- **의미** — 글로벌 빅테크 LLM에 맞서 **소버린 AI/소버린 클라우드(데이터 주권·국내 규제 대응)**가 한국 IT의 핵심 차별화 전략.

## 면접 활용 포인트 (SW 개발자 지망생용 5가지)

1. **"AI 코딩 도구는 기본기, 검증이 실력"** — 사용 여부가 아니라 "AI가 생성한 코드를 리뷰·테스트·책임지는 능력"이 차별점이다(2026년 개발자 90%가 사용).
2. **"장애 사례로 가용성·복원력을 말하라"** — 2024 크라우드스트라이크, 2025 AWS us-east-1·Cloudflare 장애로 단일 의존성 위험, 멀티리전, 점진적 배포·롤백, 변경 검증의 중요성을 설명.
3. **"클라우드 네이티브 = 쿠버네티스 + 플랫폼 엔지니어링"** — K8s가 프로덕션 표준(82%)이고 AI 워크로드 운영 플랫폼이 됐다는 사실, DevOps 다음 단계가 플랫폼 엔지니어링이라는 점.
4. **"언어 선택의 근거를 말하라"** — Python(AI/데이터), TS(타입 안정성), Go(클라우드 인프라), Rust(메모리 안전·성능)를 "왜 쓰는지"로 설명.
5. **"오픈소스 라이선스와 소버린 AI 이슈를 안다"** — Terraform→OpenTofu, Redis→Valkey 포크로 오픈소스 지속가능성을, 한국 맥락에서 네이버 HyperCLOVA X·카카오 카나나의 소버린 AI 흐름을 연결.

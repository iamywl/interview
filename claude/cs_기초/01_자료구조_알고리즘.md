# [CS] 자료구조 · 알고리즘 — PT면접 대비

> SSAFY PT면접 대비 자료. 발표 주제 후보와 핵심 개념 정리, 빈출 면접 질문과 답변 포인트를 사실·정의 중심으로 정리한다.

---

## 발표에 나올 만한 소주제

발표는 5~7분 분량으로 한 주제를 깊이 있게 다루는 것이 유리하다. 아래 후보 중 하나를 고르거나 둘을 묶어 구성한다.

1. **선형 자료구조 비교 — 배열 vs 연결리스트 vs 스택 vs 큐**: 메모리 배치와 연산별 시간복잡도 차이를 표로 정리하고 각 구조의 사용처를 제시.
2. **해시테이블과 충돌 해결**: 해시 함수, 적재율(load factor), 분리 연결법(separate chaining)과 개방 주소법(open addressing)의 트레이드오프.
3. **트리 자료구조 — BST에서 균형 트리까지**: 이진탐색트리의 한계(편향 시 O(n))와 AVL·레드블랙 트리가 이를 해결하는 원리, 힙(우선순위 큐).
4. **그래프 표현과 탐색(BFS/DFS)**: 인접 행렬 vs 인접 리스트, BFS/DFS의 동작·자료구조·시간복잡도와 활용(최단경로·위상정렬 등).
5. **정렬 알고리즘 비교 — 퀵·머지·힙 정렬**: 시간복잡도, 안정성(stability), 추가 메모리, 실무에서의 선택 기준.
6. **시간·공간 복잡도(빅오)**: 점근 표기법의 정의와 각 복잡도 클래스의 의미, 알고리즘 분석 방법.
7. **알고리즘 설계 패러다임 — 재귀·동적계획법·그리디**: 분할정복, 중복 부분문제와 메모이제이션/타뷸레이션, 그리디의 최적성 조건.

## 핵심 개념 정리 (발표용)

### 1. 배열 / 연결리스트

- **정의**: 배열은 동일 타입 원소를 연속된 메모리 공간에 저장하는 구조. 연결리스트는 각 노드가 데이터와 다음 노드 포인터를 가지는 비연속 구조.
- **특징**: 배열은 인덱스로 임의 접근(random access)이 O(1). 연결리스트는 임의 접근이 불가하여 순차 탐색이 필요하나, 노드 포인터를 알고 있으면 삽입·삭제 시 원소 이동 없이 포인터만 갱신.
- **시간복잡도**

| 연산 | 배열(Array) | 연결리스트(Linked List) |
|------|------------|------------------------|
| 임의 접근(인덱스) | O(1) | O(n) |
| 탐색(값) | O(n) | O(n) |
| 앞/중간 삽입 | O(n) | O(1)* |
| 앞/중간 삭제 | O(n) | O(1)* |

  \* 삽입/삭제 위치의 노드 포인터를 이미 가지고 있을 때. 위치를 먼저 찾아야 하면 탐색 O(n)이 추가된다.

- **사용 예**: 배열은 인덱스 기반 조회가 빈번하고 크기가 고정적인 경우. 연결리스트는 삽입·삭제가 빈번하고 크기가 동적인 경우(예: LRU 캐시의 노드 갱신).

### 2. 스택 / 큐

- **정의**: 스택은 후입선출(LIFO), 큐는 선입선출(FIFO)을 따르는 선형 자료구조.
- **특징**: 스택은 한쪽 끝(top)에서만 push/pop. 큐는 뒤(rear)에서 추가(enqueue), 앞(front)에서 제거(dequeue).
- **시간복잡도**: 스택의 push/pop, 큐의 enqueue/dequeue 모두 **O(1)**.
- **사용 예**:
  - 스택 — 함수 호출 스택(호출 시 인자·복귀 주소 push, 반환 시 pop), 수식 괄호 검사 및 후위 표기 계산, 편집기의 실행 취소(undo), DFS.
  - 큐 — 작업 스케줄링, 버퍼링, BFS(시작 노드를 enqueue 후 레벨 순서로 처리).

### 3. 해시테이블 (충돌 해결)

- **정의**: 키를 해시 함수로 인덱스(버킷)에 매핑하여 평균 O(1) 조회를 제공하는 구조.
- **충돌(collision)**: 서로 다른 키가 같은 인덱스로 매핑되는 현상. 해결법은 두 가지.
  - **분리 연결법(Separate Chaining)**: 각 버킷에 연결리스트(또는 트리)를 두고 충돌 항목을 연결. 적재율이 높거나 데이터 양을 모를 때 유리하고 삭제가 단순.
  - **개방 주소법(Open Addressing)**: 충돌 시 탐사(probing)로 다른 빈 버킷을 찾아 항목 자체를 배열에 저장. 선형 탐사·이차 탐사·이중 해싱이 있다. 포인터를 쓰지 않아 메모리 효율이 좋고 적재율이 낮을 때 빠름.
- **시간복잡도**: 평균 탐색/삽입/삭제 **O(1)**, 최악(충돌 집중 시) **O(n)**.
- **사용 예**: Java `HashMap`(분리 연결법, 자바 8 이상 버킷이 커지면 트리로 전환), Python `dict`, 중복 제거·캐시·인덱싱.

### 4. 트리 — BST · 힙 · 균형 트리

- **이진탐색트리(BST)**: 각 노드 기준 왼쪽 서브트리는 작은 값, 오른쪽은 큰 값. 균형이 맞으면 탐색/삽입/삭제 O(log n)이나, 정렬된 입력 등으로 한쪽으로 편향되면 O(n)으로 퇴화.
- **균형 트리(AVL · 레드블랙)**: 삽입·삭제 시 회전으로 높이를 O(log n)으로 유지하는 자가 균형 BST.
  - **AVL**: 좌우 서브트리 높이 차를 최대 1로 엄격히 유지 → 탐색이 빈번할 때 유리.
  - **레드블랙**: 색 규칙으로 느슨하게 균형 유지(루트~리프 최장 경로가 최단 경로의 2배 이내). 재균형 빈도가 낮아 삽입·삭제가 빈번할 때 유리.
- **힙(Heap)**: 부모-자식 간 대소 관계를 만족하는 완전 이진 트리. 최대/최소값을 O(1)에 확인, 삽입·삭제 O(log n). 우선순위 큐 구현의 기반.
- **시간복잡도**

| 구조 | 탐색 | 삽입 | 삭제 |
|------|------|------|------|
| BST (평균/균형) | O(log n) | O(log n) | O(log n) |
| BST (최악/편향) | O(n) | O(n) | O(n) |
| AVL / 레드블랙 | O(log n) | O(log n) | O(log n) |
| 힙 (최대/최소값 접근) | O(1) | O(log n) | O(log n) |

- **사용 예**: 정렬된 데이터의 범위 검색, DB 인덱스(B-트리 계열), 우선순위 큐·다익스트라 알고리즘(힙).

### 5. 그래프 — 표현과 탐색(BFS/DFS)

- **표현**
  - **인접 행렬(Adjacency Matrix)**: V×V 2차원 배열. 간선 존재 확인 O(1), 공간 O(V²). 밀집 그래프에 적합.
  - **인접 리스트(Adjacency List)**: 각 정점이 인접 정점 목록을 가짐. 공간 효율적이고 이웃 순회가 빠름. 희소 그래프에 적합.
- **탐색**
  - **BFS(너비 우선)**: 큐 사용, 시작점에서 가까운 정점부터 레벨 순서로 방문. 가중치 없는 그래프의 최단 경로.
  - **DFS(깊이 우선)**: 스택(또는 재귀) 사용, 한 경로를 끝까지 탐색 후 되돌아옴. 사이클 탐지·위상정렬·연결요소.
- **시간복잡도**

| 표현 | 공간 | 간선 확인 | BFS/DFS |
|------|------|----------|---------|
| 인접 행렬 | O(V²) | O(1) | O(V²) |
| 인접 리스트 | O(V+E) | O(degree) | O(V+E) |

### 6. 정렬 — 퀵 · 머지 · 힙

- **퀵 정렬(Quick Sort)**: 피벗 기준 분할 후 재귀. 평균 O(n log n)이나, 피벗이 항상 최소/최대로 선택되면 분할이 한쪽으로 치우쳐 **최악 O(n²)**. 제자리(in-place) 정렬, 불안정(unstable).
- **머지 정렬(Merge Sort)**: 분할 후 정렬 병합. 모든 경우 O(n log n)으로 보장, **안정 정렬**. 단, O(n) 추가 메모리 필요.
- **힙 정렬(Heap Sort)**: 힙을 구성해 최대/최소값을 반복 추출. 모든 경우 O(n log n) 보장, O(1) 추가 메모리. 불안정.
- **시간복잡도 표**

| 알고리즘 | 최선 | 평균 | 최악 | 추가 공간 | 안정성 |
|----------|------|------|------|----------|--------|
| 퀵 정렬 | O(n log n) | O(n log n) | O(n²) | O(log n)* | 불안정 |
| 머지 정렬 | O(n log n) | O(n log n) | O(n log n) | O(n) | 안정 |
| 힙 정렬 | O(n log n) | O(n log n) | O(n log n) | O(1) | 불안정 |

  \* 퀵 정렬의 추가 공간은 재귀 스택 깊이(평균 O(log n), 최악 O(n)).

- **선택 기준**: 일반적 평균 성능과 메모리 효율은 퀵 정렬. 최악 보장과 안정성이 필요하면 머지 정렬. 최악 보장 + 최소 메모리는 힙 정렬.

### 7. 탐색 (Search)

- **선형 탐색(Linear Search)**: 앞에서부터 순차 비교. 정렬 불필요, O(n).
- **이진 탐색(Binary Search)**: **정렬된** 배열에서 중앙값과 비교하며 절반씩 줄임. O(log n). 정렬 전제와 임의 접근(배열)이 필요.

| 탐색 | 전제 조건 | 시간복잡도 |
|------|----------|-----------|
| 선형 탐색 | 없음 | O(n) |
| 이진 탐색 | 정렬된 데이터 | O(log n) |

### 8. 시간 · 공간 복잡도 (빅오)

- **정의**: 빅오 표기법은 입력 크기 n이 커질 때 연산 수(시간) 또는 메모리(공간)의 증가율 상한을 나타내는 점근 표기법. 보통 **최악의 경우**를 기준으로 한다.
- **특징**: 상수 계수와 하위 항은 무시한다(예: O(n² + 2n + 1) → O(n²)). 빅오(상한) 외에 빅오메가 Ω(하한), 빅세타 Θ(상·하한 모두)가 있다.
- **복잡도 클래스(증가율 순)**: O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!).
- **사용 예**: 알고리즘 비교, 입력 규모 확장 시 성능 예측.

### 9. 재귀 · 동적계획법(DP) · 그리디

- **재귀(Recursion)**: 함수가 자기 자신을 호출해 문제를 작게 분할. 기저 조건(base case)이 필요하며, 호출마다 스택 프레임을 쓰므로 깊이가 깊으면 스택 오버플로 위험.
- **동적계획법(DP)**: 문제를 **중복되는 부분문제**로 나누고, 각 부분문제를 한 번만 풀어 결과를 저장(재계산 방지). 적용 조건은 **최적 부분구조 + 중복 부분문제**.
  - **메모이제이션(Top-down)**: 재귀로 필요한 부분문제만 풀고 결과를 캐시에 저장.
  - **타뷸레이션(Bottom-up)**: 작은 부분문제부터 반복문으로 표를 채움. 모든 부분문제를 풀어야 할 때 일반적으로 더 효율적.
  - 예: 피보나치(O(2ⁿ) → O(n)), 배낭 문제, 최장 공통 부분수열.
- **그리디(Greedy)**: 매 단계에서 그 순간 가장 좋아 보이는 선택을 한다. 빠르고 단순하나, 지역 최적이 항상 전역 최적을 보장하지 않는다. 그리디 선택 속성과 최적 부분구조가 성립할 때만 정답을 보장. 예: 다익스트라, 허프만 코딩, 활동 선택 문제.
- **DP vs 그리디**: 그리디는 한 번 정한 선택을 되돌리지 않는다. DP는 가능한 선택을 모두 고려해 저장된 결과로 최적을 조합한다. 그리디가 통하면 더 빠르지만 적용 조건 증명이 필요하다.

## 예상 면접 질문 + 답변 포인트

1. **배열과 연결리스트의 차이는?** 배열은 연속 메모리로 인덱스 임의 접근 O(1)이나 중간 삽입·삭제 시 원소 이동으로 O(n). 연결리스트는 비연속이라 임의 접근 O(n)이지만, 위치를 알면 포인터 갱신으로 삽입·삭제 O(1). 접근이 잦으면 배열, 삽입·삭제가 잦으면 연결리스트.
2. **스택과 큐의 차이와 실사용 예는?** 스택은 LIFO(함수 호출 스택, undo, 괄호 검사, DFS), 큐는 FIFO(작업 스케줄링, 버퍼, BFS). 양쪽 모두 핵심 연산은 O(1).
3. **해시 충돌이 무엇이고 어떻게 해결하나?** 서로 다른 키가 같은 버킷에 매핑되는 것. 분리 연결법(버킷에 리스트/트리 연결)과 개방 주소법(탐사로 빈 버킷 탐색). 적재율이 높으면 연결법, 낮으면 개방 주소법이 유리.
4. **해시테이블이 평균 O(1)인데 최악이 O(n)인 이유는?** 해시 함수가 균등 분포일 때 평균 O(1). 모든 키가 한 버킷에 몰리면 사실상 리스트 탐색이 되어 O(n). 좋은 해시 함수와 적재율 관리(리해싱)가 중요.
5. **이진탐색트리가 O(n)으로 퇴화하는 경우와 해결책은?** 정렬된 데이터를 순서대로 삽입하면 한쪽으로 편향되어 사실상 연결리스트가 됨. AVL·레드블랙 같은 자가 균형 트리가 회전으로 높이를 O(log n)으로 유지해 해결.
6. **AVL과 레드블랙 트리의 차이는?** 둘 다 O(log n) 보장. AVL은 높이 차 1 이내로 엄격히 균형 → 탐색 빈번 시 유리. 레드블랙은 느슨하게 균형, 재균형 빈도가 낮아 삽입·삭제 빈번 시 유리.
7. **힙은 무엇이고 어디에 쓰나?** 부모-자식 대소 관계를 만족하는 완전 이진 트리. 최대/최소값 접근 O(1), 삽입·삭제 O(log n). 우선순위 큐, 다익스트라, 힙 정렬에 사용.
8. **인접 행렬과 인접 리스트 중 언제 무엇을 쓰나?** 밀집 그래프나 간선 존재 확인이 잦으면 인접 행렬(확인 O(1), 공간 O(V²)). 희소 그래프나 이웃 순회가 잦으면 인접 리스트(공간 O(V+E)).
9. **BFS와 DFS의 차이와 자료구조는?** BFS는 큐로 가까운 정점부터 레벨 순 방문(무가중 최단 경로). DFS는 스택/재귀로 한 경로를 끝까지 탐색(사이클 탐지·위상정렬). 인접 리스트 기준 둘 다 O(V+E).
10. **퀵 정렬의 최악 케이스는 언제이고 왜 그런가?** 피벗이 항상 최소 또는 최대로 선택될 때(예: 이미 정렬된 배열에서 끝 원소를 피벗으로). 분할이 한쪽으로 치우쳐 깊이가 n이 되어 O(n²). 랜덤 피벗·중앙값 피벗으로 완화.
11. **퀵·머지·힙 정렬 중 무엇을 언제 쓰나?** 평균 성능과 메모리 효율은 퀵. 최악 O(n log n) 보장과 안정성이 필요하면 머지(단 O(n) 추가 메모리). 최악 보장 + 최소 메모리는 힙.
12. **안정 정렬(stable sort)이란? 왜 중요한가?** 동일 키 원소의 원래 순서가 정렬 후에도 유지되는 성질. 머지 정렬은 안정, 퀵·힙은 불안정. 다중 기준 정렬에서 중요.
13. **빅오 표기법이 무엇이고 왜 최악의 경우를 보나?** 입력 크기 증가에 따른 시간/공간 증가율의 상한을 나타내는 점근 표기. 상수·하위 항은 무시. 최악의 경우는 성능 보장을 위한 상한을 제공하기 때문에 기준으로 삼는다.
14. **재귀와 반복(iteration)의 차이는?** 재귀는 호출마다 스택 프레임을 사용해 깊으면 스택 오버플로 위험이 있으나 코드가 간결. 반복은 추가 스택을 쓰지 않아 메모리 효율적.
15. **동적계획법은 언제 쓰나? 그리디와 무엇이 다른가?** DP는 최적 부분구조와 중복 부분문제가 있을 때 부분문제 결과를 저장해 재계산을 막는다. 그리디는 매 단계 지역 최적을 선택하며 되돌리지 않아 빠르지만, 그리디 선택 속성이 성립해야 전역 최적을 보장.
16. **메모이제이션과 타뷸레이션의 차이는?** 메모이제이션은 top-down(재귀+캐시)으로 필요한 부분문제만 계산. 타뷸레이션은 bottom-up(반복+표)으로 작은 것부터 모두 계산.
17. **이진 탐색의 전제 조건과 복잡도는?** 데이터가 정렬되어 있어야 하고 임의 접근이 가능해야 함. 매 단계 탐색 범위를 절반으로 줄여 O(log n).

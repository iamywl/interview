## 핵심 개념 발표용 정리

### 1. 객체지향 4대 특징

- **캡슐화(Encapsulation)**: 데이터(필드)와 메서드를 클래스로 묶고 외부 직접 접근을 제한. 내부 구현 은닉으로 무결성 보호. (예: `private` 필드 + getter/setter)
- **상속(Inheritance)**: 한 클래스가 다른 클래스의 속성·동작을 물려받음. 코드 재사용·계층 구조. (예: `extends`)
- **다형성(Polymorphism)**: 동일한 호출이 객체의 실제 타입에 따라 다르게 동작. 오버라이딩(런타임)·오버로딩(컴파일타임)으로 실현.
- **추상화(Abstraction)**: 복잡한 구현을 숨기고 본질적 기능(인터페이스)만 노출. (예: 추상클래스, 인터페이스)

### 2. SOLID 5원칙

- **S — 단일 책임(SRP)**: 클래스는 변경 이유가 단 하나.
- **O — 개방-폐쇄(OCP)**: 확장에는 열려 있고 수정에는 닫혀 있어야.
- **L — 리스코프 치환(LSP)**: 상위 타입 객체를 하위 타입으로 치환해도 정확성 유지.
- **I — 인터페이스 분리(ISP)**: 사용하지 않는 인터페이스에 의존 강요 금지. 큰 인터페이스를 작게 분리.
- **D — 의존성 역전(DIP)**: 상위·하위 모듈 모두 추상화에 의존. 세부사항이 추상화에 의존.

### 3. 오버로딩 vs 오버라이딩

| 구분 | 오버로딩 | 오버라이딩 |
|------|----------|------------|
| 정의 | 같은 클래스, 같은 이름, 다른 매개변수 | 상위 클래스 메서드를 하위에서 같은 시그니처로 재정의 |
| 다형성 | 컴파일타임(정적) | 런타임(동적) |
| 결정 시점 | 컴파일 시 인자에 따라 | 실행 시 실제 객체 타입에 따라 |
| 상속 필요 | 불필요 | 필요 |

### 4. 추상클래스 vs 인터페이스 (Java 기준)

- **공통점**: 둘 다 인스턴스화 불가, 구현된/안 된 메서드 혼합 가능.
- **차이점**: 추상클래스는 비-static 필드·다양한 접근제어자 구체 메서드 가능, **단일 상속**. 인터페이스 필드는 `public static final`, 메서드는 `public`, **다중 구현** 가능.
- **선택**: 관련 클래스가 공통 코드/상태 공유 → 추상클래스, 무관한 클래스의 공통 계약 → 인터페이스(예: `Comparable`).

### 5. 상속 vs 합성(Composition)

- **상속**: 기존 클래스 확장으로 재사용. 강한 결합, 상위 변경이 하위에 전파.
- **합성**: 다른 클래스 인스턴스를 필드로 포함해 위임(delegation). 느슨한 결합, 런타임 동작 교체 가능.
- **합성 우선 원칙**: 다형적 동작·재사용은 상속보다 합성으로. 전략·데코레이터 패턴이 활용.

### 6. 대표 디자인 패턴

- **싱글톤(생성)**: 인스턴스가 단 하나만 존재하도록 보장 + 전역 접근점. 공유 자원 제어에 사용. **문제점**: 결합 은폐, 멀티스레드 동기화 필요, 단위 테스트(Mock 대체) 어려움.
- **팩토리(생성)**: 객체 생성 인터페이스를 상위 클래스가 제공, 생성 타입은 하위가 결정. 생성 로직과 사용 분리.
- **옵저버(행위)**: 주체(Subject) 상태 변화를 구독 객체들에 자동 통지. 이벤트 기반 시스템.
- **전략(행위)**: 알고리즘 군을 캡슐화해 런타임 교체. 합성 기반으로 동작 일부를 전략 객체로 교체.

### 7. MVC

- **Model**(데이터·비즈니스 로직), **View**(화면 표시), **Controller**(입력 처리·Model/View 연결). 핵심 가치는 **관심사 분리(Separation of Concerns)**로 유지보수성 향상.

### 8. 결합도와 응집도

- **결합도(Coupling)**: 모듈 간 상호의존 정도. **낮을수록** 좋음.
- **응집도(Cohesion)**: 모듈 내 요소가 단일 목적에 협력하는 정도. **높을수록** 좋음.
- **목표**: 낮은 결합도 + 높은 응집도.

### 9. 모놀리식 vs 마이크로서비스(MSA)

- **모놀리식**: 전체를 하나로 빌드·배포. 장점 — 단순, 낮은 지연·일관성, 초기 속도. 단점 — 확장성·기술 유연성 부족, 장애 전파.
- **마이크로서비스**: 독립 배포 가능한 작은 서비스. 장점 — 서비스별 독립 확장·기술 자유·장애 격리. 단점 — 분산 복잡도·네트워크 지연·데이터 일관성·DevOps 비용.
- **Martin Fowler "Monolith First"(2015)**: 대부분 성공적 MSA는 커진 모놀리식을 분해한 것. 초기엔 모놀리식, 한계가 드러날 때 분해 권장.

### 10. 웹/HTTP 기초

- **프론트엔드/백엔드**: 프론트는 UI·표시, 백엔드는 데이터·로직·영속성.
- **동기 vs 비동기**: 동기는 완료까지 차단(blocking), 비동기는 완료를 안 기다리고(non-blocking) 진행. 단일/다중 스레드 여부와 독립 개념.
- **프로세스 vs 스레드**: 프로세스는 독립 메모리 실행 단위, 스레드는 프로세스 내 실행 흐름. 단일 스레드는 동기 대기 중 다른 일 못 함 → 서버는 멀티스레드/비동기 I/O로 동시성 확보.
- **인증(Authentication)** = "누구인가" 증명, **인가(Authorization)** = "무엇이 허용되는가" 결정.
  - **세션**: 서버가 세션 저장(stateful), 쿠키에 세션 ID. 확장 시 공유 저장소(Redis) 필요.
  - **JWT**: 서명 토큰에 정보 담아 발급, 서버 무상태(stateless) → 확장 유리, 즉시 폐기 어려움.
  - **OAuth 2.0**: 제3자에게 리소스 접근을 위임하는 **인가 프레임워크**(소셜 로그인에 활용, 인증 자체 표준은 OpenID Connect).
- **CORS**: 서버가 다른 출처(origin)의 리소스 로딩 허용 여부를 브라우저에 알리는 HTTP 헤더 메커니즘. 부수 효과 가능 요청은 실제 요청 전 `OPTIONS` **사전 요청(preflight)**으로 확인.
- **HTTP 캐싱**: `Cache-Control`로 정책(max-age·no-store·public/private) 지정. `ETag`는 버전 식별자로 `If-None-Match` 재검증 시 변경 없으면 `304 Not Modified`로 대역폭 절약.

## 예상 면접 질문 + 답변 포인트

1. **객체지향 4대 특징은?** 캡슐화(묶고 은닉), 상속(물려받아 재사용), 다형성(타입별 다른 동작), 추상화(핵심만 노출).
2. **SOLID 원칙은?** SRP(책임 하나), OCP(확장 개방·수정 폐쇄), LSP(하위 타입 치환), ISP(불필요 의존 금지), DIP(추상화 의존). 목적은 유지보수·확장성.
3. **오버로딩과 오버라이딩의 차이는?** 오버로딩=같은 클래스·다른 매개변수·컴파일타임(정적), 오버라이딩=상속 관계·같은 시그니처 재정의·런타임(동적).
4. **추상클래스와 인터페이스의 차이는?** 추상클래스는 상태·다양한 접근제어자·단일 상속, 인터페이스는 `public static final` 필드·다중 구현. 코드 공유→추상클래스, 공통 계약→인터페이스.
5. **다형성이 왜 유용한가?** 클라이언트가 구체 타입이 아닌 상위 타입/인터페이스에 의존 → 새 구현 추가해도 호출 코드 불변(OCP·DIP 연결).
6. **상속보다 합성을 선호하는 이유는?** 상속은 강한 결합·변경 전파, 합성은 위임 기반 느슨한 결합·런타임 교체 가능. 전략·데코레이터 패턴이 예.
7. **싱글톤 패턴과 문제점은?** 인스턴스 하나 보장+전역 접근점. 문제: 전역 상태로 결합 은폐, 멀티스레드 동기화 필요, 테스트 어려움.
8. **디자인 패턴 하나 설명(전략 패턴).** 알고리즘 군을 캡슐화해 런타임 교체. 합성 기반으로 동작을 전략 객체로 교체, 조건 분기 대신 다형적 위임.
9. **옵저버 패턴은 언제 쓰나?** 한 객체 상태 변화를 다수 객체에 자동 통지할 때. 구독/해지로 발행자-구독자 결합을 낮춤(이벤트 기반).
10. **결합도와 응집도란?** 결합도=모듈 간 의존(낮을수록 좋음), 응집도=모듈 내 단일 목적 집중(높을수록 좋음). 목표는 낮은 결합도+높은 응집도.
11. **MVC 패턴은?** Model(데이터·로직)·View(표시)·Controller(연결). 핵심은 관심사 분리.
12. **모놀리식과 MSA의 장단점은?** 모놀리식: 단순·일관성·초기 속도 vs 확장·격리 약함. MSA: 독립 확장·기술 자유·격리 vs 분산 복잡도·지연·일관성·비용. Fowler는 "모놀리식 먼저".
13. **동기와 비동기의 차이는?** 동기는 완료까지 차단, 비동기는 안 기다리고 진행. 단일/다중 스레드와 별개.
14. **프로세스와 스레드의 차이(서버 관점)?** 프로세스는 독립 메모리 실행 단위, 스레드는 프로세스 내 흐름. 단일 스레드는 동기 대기 중 다른 요청 처리 못 함 → 멀티스레드/비동기 I/O로 동시성.
15. **세션과 JWT의 차이는?** 세션은 stateful(서버 저장, 확장 시 공유 저장소), JWT는 stateless(서명 토큰, 확장 유리, 즉시 폐기 어려움).
16. **OAuth는 인증인가 인가인가?** 본질은 제3자 리소스 접근 위임하는 **인가** 프레임워크. 소셜 로그인에 결합되지만 인증 자체 표준은 OpenID Connect.
17. **CORS는 무엇이며 preflight는 언제?** 다른 출처 접근 허용 여부를 알리는 HTTP 헤더 메커니즘. 부수 효과 가능 요청에서 브라우저가 실제 요청 전 `OPTIONS` 사전 요청.
18. **Cache-Control과 ETag의 역할 차이는?** Cache-Control은 캐시 정책(재사용 기간) 지정, ETag는 버전 식별자로 재검증해 변경 없으면 304로 대역폭 절약.

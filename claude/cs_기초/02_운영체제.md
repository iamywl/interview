# [CS] 운영체제(OS) — PT면접 대비

## 발표에 나올 만한 소주제

SSAFY PT면접에서 운영체제 주제로 자주 등장하는 발표 후보다. 6~8분 분량으로 핵심 정의와 비교, 트레이드오프를 정리해 발표하면 적합하다.

1. **프로세스와 스레드의 차이, 그리고 멀티프로세싱 vs 멀티스레딩** — 자원 공유 모델과 비용 차이가 핵심.
2. **CPU 스케줄링 알고리즘 비교(FCFS·SJF·RR·우선순위)** — 각 알고리즘의 목표 지표(대기시간·응답시간·기아)와 트레이드오프.
3. **동기화와 교착상태(임계구역·뮤텍스·세마포어·데드락 4조건과 예방)** — 동시성 제어의 정의와 데드락 처리 전략.
4. **가상 메모리와 메모리 관리(페이징·세그멘테이션·요구 페이징)** — 물리 메모리보다 큰 주소공간을 제공하는 메커니즘.
5. **페이지 교체 알고리즘(FIFO·LRU·Optimal)과 Belady's Anomaly** — 페이지 폴트를 줄이기 위한 교체 정책.
6. **캐시와 지역성(Locality of Reference)** — 시간/공간 지역성을 활용한 성능 향상.
7. **인터럽트와 시스템 콜(사용자 모드 vs 커널 모드)** — 권한 전환과 운영체제 진입 경로.
8. **컨텍스트 스위칭과 그 비용** — 문맥 전환 시 발생하는 오버헤드의 구성 요소.

## 핵심 개념 발표용 정리

### 1. 프로세스 vs 스레드

- **프로세스(Process)**: 실행 중인 프로그램. 자체 주소공간(코드·데이터·힙·스택)과 자원을 가진 독립적 실행 환경.
- **스레드(Thread)**: 프로세스 내 실행의 최소 단위. 같은 프로세스의 스레드들은 코드·데이터·힙·주소공간을 **공유**하고, 각자 별도의 스택과 레지스터(PC 포함)를 가진다.
- 스레드는 자원을 공유하므로 생성·컨텍스트 스위칭 비용이 프로세스보다 작고, 필요한 시스템 콜도 적다. 한 프로세스는 여러 스레드를 가질 수 있다.

### 2. 멀티프로세싱 vs 멀티스레딩

- **멀티프로세싱**: 여러 프로세스 사용. 독립 주소공간으로 **격리성·안정성**이 높다(한 프로세스 장애가 전파되지 않음). 대신 IPC 비용·메모리 사용이 크다.
- **멀티스레딩**: 한 프로세스 내 여러 스레드. 메모리 공유로 통신이 빠르고 가볍지만, 공유 데이터에 대한 **동기화 문제**(경쟁 상태·데드락)와 한 스레드 비정상 종료가 프로세스 전체에 영향을 줄 위험이 있다.

### 3. 컨텍스트 스위칭(Context Switching)

- CPU가 한 작업에서 다른 작업으로 전환할 때 현재 실행 상태를 저장하고 다음 상태를 복원하는 과정. 대상은 레지스터·PC·스택 포인터 등이며 **PCB(Process Control Block)**에 저장·로드한다.
- **비용(오버헤드)**: 레지스터 저장/복원, 주소공간 변경 시 **TLB 플러시**와 이후 TLB 미스, 캐시 오염, 스케줄러 실행 비용. 스위칭 자체는 유용한 작업을 하지 않으므로 빈번하면 처리량이 떨어진다.

### 4. CPU 스케줄링 알고리즘

| 알고리즘 | 방식 | 특징 / 트레이드오프 |
|---|---|---|
| **FCFS** | 비선점, 도착 순서 | 단순. **Convoy effect**(긴 작업이 앞서면 짧은 작업들이 오래 대기) |
| **SJF** | 비선점, 버스트 짧은 순 | 평균 대기시간 **최소**. 버스트 예측 필요, 긴 작업 **기아** 가능 |
| **SRTF** | SJF의 선점형 | 남은 실행시간이 가장 짧은 작업 선점 |
| **Round Robin(RR)** | 선점, 고정 시간할당량(quantum) | 시분할용, **공정성**. quantum 작으면 응답성↑·스위칭↑, 크면 FCFS 수렴 |
| **Priority** | 우선순위 높은 작업 우선 | 중요 작업 우선. 낮은 우선순위 **기아** → **에이징(aging)**으로 완화 |

### 5. 동기화(Synchronization)

- **임계구역(Critical Section)**: 둘 이상이 공유 자원에 접근하는 코드 영역. 한 번에 하나만 진입(상호 배제).
- **뮤텍스(Mutex)**: 잠금 메커니즘. 한 번에 하나의 스레드만 점유하며 **소유권**이 있어 **잠근 스레드만 해제**.
- **세마포어(Semaphore)**: 신호 메커니즘. 카운터를 `wait(P)`/`signal(V)` 원자 연산으로 관리. 소유권이 없어 한 스레드가 wait, 다른 스레드가 signal 가능. 이진/카운팅 세마포어가 있다.

### 6. 데드락(Deadlock) — 4조건과 예방

**발생 필요조건(Coffman conditions)** — 네 조건이 **동시에** 성립해야 발생:
1. **상호 배제**: 자원을 한 번에 한 프로세스만 사용.
2. **점유와 대기**: 자원을 점유한 채 다른 자원을 추가로 기다림.
3. **비선점**: 점유 프로세스가 자발적으로만 반납.
4. **순환 대기**: 프로세스들이 원형으로 서로의 자원을 대기.

**예방**: 네 조건 중 하나 이상을 깬다. 앞 세 조건은 현실적으로 깨기 어려워 보통 **순환 대기 제거**(자원에 전역 순서 부여)를 쓴다.
**처리 4전략**: 예방(Prevention), 회피(Avoidance, 은행원 알고리즘), 탐지 및 복구(Detection & Recovery), 무시(Ostrich).

### 7. 가상 메모리 / 메모리 관리

- **가상 메모리**: 물리 메모리 크기와 무관하게 크고 연속적인 주소공간을 제공하는 추상화. 안 쓰는 페이지는 디스크(swap)로 내보냄.
- **페이징**: 고정 크기 **페이지(논리)/프레임(물리)**으로 분할. 외부 단편화 없음, 페이지 테이블로 매핑.
- **세그멘테이션**: 코드·데이터·스택 등 **가변 크기 논리 단위**로 분할.
- **요구 페이징**: 실제 접근 시점에만 적재. 없는 페이지 접근 시 **페이지 폴트** 발생 → OS가 디스크에서 적재 후 페이지 테이블 갱신.

### 8. 페이지 교체 알고리즘

- **FIFO**: 가장 오래 적재된 페이지 교체. 단순하나 **Belady's Anomaly**(프레임 늘렸는데 폴트 증가)가 발생할 수 있는 대표 알고리즘.
- **LRU**: 가장 오랫동안 사용 안 된 페이지 교체. 스택 기반이라 Belady's Anomaly 없음.
- **Optimal(OPT)**: 가장 늦게 쓰일 페이지 교체. 폴트율 이론상 최저이나 미래 참조를 알아야 해 구현 불가 — 비교 기준.

### 9. 캐시와 지역성(Locality of Reference)

- **캐시**: CPU와 주기억장치 사이 빠른 소용량 메모리. 자주 쓰는 데이터를 보관해 접근 시간 단축.
- **시간 지역성**: 최근 접근한 위치가 곧 다시 접근될 가능성이 높다(반복문·변수).
- **공간 지역성**: 접근한 위치 근처가 곧 접근될 가능성이 높다(배열 순회).

### 10. 파일 시스템 / 인터럽트·시스템 콜

- **파일 시스템**: 디스크 데이터를 파일·디렉터리로 조직·저장·검색. 메타데이터 관리(예: Unix/Linux의 **inode**). 대표: ext4, NTFS, FAT32, XFS.
- **사용자 모드 vs 커널 모드**: 특권 명령(I/O·메모리 관리)은 커널 모드에서만 실행 가능.
- **시스템 콜**: 사용자 프로그램이 특권 연산을 OS에 요청하는 인터페이스. **trap(소프트웨어 인터럽트)**으로 커널 모드 진입.
- **인터럽트**: 하드웨어 장치가 **비동기적**으로 발생시키는 신호(타이머·I/O 완료). **트랩/예외**는 현재 명령에 의해 **동기적**으로 발생(0 나누기·페이지 폴트). 구분: 인터럽트=비동기, 트랩/시스템 콜=동기.

## 예상 면접 질문 + 답변 포인트

1. **프로세스와 스레드의 차이는?** 프로세스는 독립 주소공간을 가진 실행 단위, 스레드는 프로세스 내 실행의 최소 단위로 코드·데이터·힙을 공유하고 스택·레지스터는 따로 가진다. 스레드는 생성·전환 비용이 작다.
2. **멀티프로세싱과 멀티스레딩의 선택 기준은?** 안정성·격리가 중요하면 프로세스(IPC·메모리 비용 큼), 빠른 데이터 공유·경량성이 중요하면 스레드(동기화 문제·장애 전파 위험).
3. **컨텍스트 스위칭이란? 비용은 왜 발생하나?** 실행 상태(레지스터·PC)를 PCB에 저장·복원하는 과정. 레지스터 저장/복원, TLB 플러시·미스, 캐시 오염, 스케줄러 비용이 오버헤드.
4. **FCFS·SJF·RR·우선순위 비교?** FCFS는 Convoy effect, SJF는 평균 대기 최소이나 기아·예측 필요, RR은 공정성·응답성(quantum 의존), 우선순위는 기아 발생→에이징 완화.
5. **Round Robin에서 time quantum 크기의 영향은?** 작으면 응답성↑·스위칭 오버헤드↑, 크면 FCFS 수렴. 보통 대부분의 CPU 버스트보다 약간 큰 값 권장.
6. **뮤텍스와 세마포어의 차이는?** 뮤텍스는 소유권 있는 잠금(상호 배제, 잠근 스레드만 해제), 세마포어는 소유권 없는 신호(wait/signal 서로 다른 스레드 가능). 자원 보호=뮤텍스, 신호·조정=세마포어.
7. **이진 세마포어와 뮤텍스는 같은가?** 형태는 비슷하나 다르다. 뮤텍스는 소유권 강제·상호 배제 목적, 이진 세마포어는 소유권 없음·신호 목적.
8. **데드락 4조건과 예방은?** 상호 배제·점유와 대기·비선점·순환 대기가 동시 성립 시 발생. 예방은 하나 이상을 깸. 보통 자원 전역 순서로 순환 대기 제거.
9. **데드락 처리 전략은?** 예방, 회피(은행원 알고리즘), 탐지 및 복구, 무시(ostrich).
10. **교착상태와 기아의 차이는?** 데드락은 상호 순환 대기로 어느 쪽도 진행 못 함(4조건 성립). 기아는 우선순위에 밀려 무한 지연. 기아는 에이징으로 완화.
11. **가상 메모리란? 왜 필요한가?** 물리 메모리와 무관하게 크고 연속적인 주소공간 제공. 큰 프로그램 실행·프로세스 격리·효율적 메모리 활용 가능.
12. **페이징과 세그멘테이션의 차이는?** 페이징은 고정 크기로 외부 단편화 없음(내부 단편화 가능), 세그멘테이션은 논리 단위 가변 크기로 외부 단편화 가능.
13. **페이지 폴트가 발생하면?** 접근 페이지가 메모리에 없을 때 발생. OS가 디스크에서 적재(빈 프레임 없으면 교체 알고리즘으로 희생 페이지 선택), 페이지 테이블 갱신 후 명령 재실행.
14. **LRU와 FIFO의 차이, Belady's Anomaly란?** FIFO는 가장 오래된 페이지, LRU는 가장 오래 미사용 페이지 교체. Belady's Anomaly는 프레임 수를 늘렸는데 폴트가 증가하는 현상으로 FIFO에서 발생. LRU·Optimal은 발생 안 함.
15. **캐시의 지역성이란?** 시간 지역성(최근 접근 위치 재접근)과 공간 지역성(근처 접근). 캐시는 이를 이용해 적중률을 높여 평균 접근 시간 단축.
16. **시스템 콜과 인터럽트의 차이는?** 시스템 콜은 trap으로 동기적 커널 진입(특권 연산 요청), 인터럽트는 하드웨어가 비동기적으로 발생시키는 신호.
17. **사용자/커널 모드를 구분하는 이유는?** 특권 명령을 사용자 프로그램이 직접 못 하게 막아 시스템 보호. 사용자 프로그램은 시스템 콜로만 커널 기능 요청.
18. **임계구역 문제의 해결 조건은?** 상호 배제, 진행(Progress), 한정 대기(Bounded Waiting).

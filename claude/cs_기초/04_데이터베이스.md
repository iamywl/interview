# [CS] 데이터베이스(DB) — PT면접 대비

> SSAFY PT면접(발표면접) 대비 자료. 주제: 데이터베이스. 사실·정의 중심으로 정리하며, 각 항목의 근거는 하단 참고문헌에 링크로 명시한다.

## 발표에 나올 만한 소주제

PT면접에서는 5~7분 발표 + 꼬리질문이 일반적이다. "정의 → 동작 원리 → 장단점 → 실무 적용/선택 기준" 순서가 안정적이다.

1. **관계형(RDB) vs NoSQL — 데이터 모델과 선택 기준**
2. **정규화(1NF~3NF)와 반정규화 — 데이터 무결성과 성능의 트레이드오프**
3. **트랜잭션과 ACID — 데이터 정합성 보장 메커니즘**
4. **격리수준(Isolation Level)과 동시성 이상현상** (dirty / non-repeatable / phantom read)
5. **인덱스(B-Tree·해시·클러스터드) — 조회 성능 향상의 원리와 비용**
6. **락(Lock)·데드락과 동시성 제어**
7. **샤딩·레플리케이션·CAP 정리 — 분산 데이터베이스의 확장성과 일관성**
8. **키(Key)와 JOIN — 관계형 모델의 관계 표현**

## 핵심 개념 발표용 간결 정리

### 1. 관계형(RDB) vs NoSQL

- **RDBMS**: 데이터를 행·열 테이블에 저장, 테이블 간 관계를 외래키로 표현. 사전 정의된 스키마 강제, SQL 질의, ACID 트랜잭션 기본 제공. (MySQL, PostgreSQL, Oracle)
- **NoSQL**: 고정 스키마 없이 다양한 모델 — 문서형(MongoDB), 키-값(Redis), 컬럼 패밀리(Cassandra), 그래프(Neo4j).
- **차이의 핵심**: RDB는 정합성·정규화·복잡한 JOIN/트랜잭션·수직 확장 중심. NoSQL은 스키마 유연성·대용량 분산·수평 확장(샤딩) 중심이며 많은 경우 강한 일관성을 완화(최종 일관성).

### 2. 정규화(Normalization)

데이터 중복을 줄이고 무결성을 유지하기 위해 테이블을 분해하는 단계적 절차. 삽입·갱신·삭제 이상현상을 방지.

- **1NF**: 모든 컬럼이 원자값, 반복 그룹 없음.
- **2NF**: 1NF + **부분 함수 종속** 제거(모든 비주요 속성이 기본키 전체에 종속).
- **3NF**: 2NF + **이행적 종속** 제거(비주요 속성이 다른 비주요 속성에 종속되면 안 됨).
- **BCNF**: 3NF 강화. 모든 결정자가 후보키여야 함.
- **반정규화**: 조회 성능을 위해 의도적으로 중복 허용·테이블 통합. JOIN·집계 비용을 줄이나 갱신 이상·정합성 부담 증가. 읽기 부하가 크고 쓰기가 적을 때 고려.

### 3. 트랜잭션과 ACID

트랜잭션은 하나의 논리적 작업 단위. ACID는 4가지 속성:
- **Atomicity(원자성)**: 전부 성공 또는 전부 실패(All or Nothing).
- **Consistency(일관성)**: 유효 상태에서 유효 상태로만 전이(제약조건 유지).
- **Isolation(격리성)**: 동시 실행이 순차 실행과 같은 결과를 보장.
- **Durability(지속성)**: 커밋된 변경은 장애에도 손실되지 않음.

### 4. 격리수준(Isolation Level)과 이상현상

**3가지 이상현상**
- **Dirty Read**: 미커밋 데이터를 읽음. 상대가 롤백하면 존재한 적 없는 값을 읽은 것.
- **Non-repeatable Read**: 같은 **행**을 재조회 시 값이 달라짐(UPDATE/DELETE 영향).
- **Phantom Read**: 같은 **조건**으로 재조회 시 행 개수가 달라짐(INSERT 영향).

**격리수준별 방지 범위**

| 격리수준 | Dirty Read | Non-repeatable Read | Phantom Read |
|---|---|---|---|
| READ UNCOMMITTED | 발생 | 발생 | 발생 |
| READ COMMITTED | 방지 | 발생 | 발생 |
| REPEATABLE READ | 방지 | 방지 | 발생 |
| SERIALIZABLE | 방지 | 방지 | 방지 |

> 구현 차이: MySQL InnoDB 기본값은 REPEATABLE READ(갭 락으로 팬텀 상당 부분 방지), PostgreSQL 기본값은 READ COMMITTED(REPEATABLE READ는 스냅샷 격리로 구현).

### 5. 인덱스(Index)

조회 속도를 높이기 위한 별도 자료구조. WHERE/JOIN/ORDER BY 대상 컬럼 검색을 빠르게.

- **B-Tree(B+Tree)**: 가장 일반적. 균형 트리로 O(log n), **범위 검색·정렬·부등호 조건**에 강함. 대부분 RDBMS의 기본 인덱스.
- **해시(Hash)**: 해시 함수로 위치 계산, **등치 비교(=)**에 매우 빠름. 범위 검색·정렬 불가.
- **클러스터드**: 인덱스 순서대로 **실제 데이터 행을 물리적으로 정렬·저장**. 테이블당 1개. 범위 조회 유리, 비순차 키 삽입 시 페이지 분할 비용.
- **논클러스터드**: 데이터와 분리된 구조, 행 포인터 보유. 테이블당 여러 개.
- **단점(꼬리질문 빈출)**: 추가 저장 공간, 쓰기(INSERT/UPDATE/DELETE) 시 인덱스 갱신으로 **쓰기 성능 저하**, 카디널리티 낮은 컬럼은 효율 낮음.

### 6. 키(Key)

- **후보키**: 행을 유일 식별하는 최소 속성 집합. **기본키**: 후보키 중 대표(NULL 불가·유일). **대체키**: 기본키로 선정 안 된 후보키. **외래키**: 다른 테이블의 키를 참조해 참조 무결성 보장. **슈퍼키**: 유일 식별 가능 속성 집합(최소성 불필요).

### 7. JOIN의 종류

- **INNER**: 조인 조건 일치 행만. **LEFT/RIGHT OUTER**: 한쪽 전체 + 반대쪽 일치(없으면 NULL). **FULL OUTER**: 양쪽 전체. **CROSS**: 카티션 곱. **SELF**: 자기 자신과 조인.

### 8. 락(Lock)·데드락

- **Lock**: 동시 접근 제어. 공유 락(S, 읽기)·배타 락(X, 쓰기).
- **2PL(Two-Phase Locking)**: 락 획득만 하는 확장 단계 + 해제만 하는 수축 단계로 직렬성 보장(비관적 동시성 제어).
- **데드락**: 트랜잭션들이 서로의 락 해제를 순환 대기. 해결: 예방, 회피, 탐지 후 victim 롤백.

### 9. 샤딩·레플리케이션·CAP

- **레플리케이션**: 데이터를 여러 노드에 복제. 읽기 분산·가용성·내결함성↑ (Primary-Replica).
- **샤딩**: 샤드 키 기준 **수평 분할** 저장. 쓰기·용량 수평 확장. 단, 교차 샤드 JOIN·트랜잭션 어려움.
- **CAP 정리**: 분산 시스템에서 일관성(C)·가용성(A)·분할 내성(P)을 동시에 모두 보장 불가, 최대 2개. 네트워크 분할은 불가피하므로 P 필수, 분할 시 **C와 A 중 선택**(CP 또는 AP). 많은 NoSQL은 AP + 최종 일관성.

## 예상 면접 질문 + 답변 포인트

1. **정규화란? 왜 하는가?** 중복을 줄이고 무결성을 유지하기 위해 테이블을 분해하는 절차. 삽입·갱신·삭제 이상 방지. 1NF(원자값)→2NF(부분 종속 제거)→3NF(이행 종속 제거). 단점은 JOIN 증가, 이때 반정규화 고려.
2. **반정규화는 언제 하는가?** 읽기 부하가 쓰기보다 훨씬 크고 조회 성능이 중요할 때 중복을 허용해 JOIN·집계 비용을 줄임. 대신 정합성 동기화 부담 증가.
3. **트랜잭션의 ACID는?** 원자성(전부/전무), 일관성(유효 상태 유지), 격리성(순차 실행과 동일), 지속성(커밋 후 영속). 로그(WAL)·락/MVCC로 구현.
4. **격리수준 4가지와 발생 이상현상은?** READ UNCOMMITTED(모두 발생), READ COMMITTED(dirty 방지), REPEATABLE READ(non-repeatable까지), SERIALIZABLE(모두 방지). 높을수록 동시성↓. MySQL InnoDB=REPEATABLE READ, PostgreSQL=READ COMMITTED 기본.
5. **dirty/non-repeatable/phantom read의 차이는?** dirty=미커밋 읽기, non-repeatable=같은 행 재조회 시 값 변경, phantom=같은 조건 재조회 시 행 개수 변경(INSERT).
6. **인덱스의 동작 원리와 단점은?** 대부분 B-Tree로 O(log n), 범위·정렬에 유리. 단점은 추가 저장 공간, 쓰기 시 인덱스 갱신 비용, 카디널리티 낮은 컬럼 비효율. 무분별한 인덱스는 성능 저하.
7. **클러스터드와 논클러스터드 인덱스의 차이는?** 클러스터드는 실제 데이터를 물리 정렬·저장(테이블당 1개, 범위 조회 유리), 논클러스터드는 분리 구조로 행 포인터 보유(여러 개 가능).
8. **B-Tree와 해시 인덱스의 차이는?** 해시는 등치(=)에 매우 빠르나 범위·정렬 불가, B-Tree는 등치·범위·정렬 모두 지원해 범용적.
9. **RDB와 NoSQL의 선택 기준은?** 데이터 구조가 명확하고 관계·정합성·트랜잭션이 중요하면 RDB, 스키마가 자주 바뀌거나 비정형·대용량·높은 쓰기·수평 확장이 필요하면 NoSQL.
10. **기본키·외래키·후보키·슈퍼키의 차이는?** 슈퍼키(유일 식별 집합)⊃후보키(최소성 만족)⊃기본키(대표, NULL 불가). 외래키는 다른 테이블 키 참조로 참조 무결성 보장.
11. **JOIN의 종류는?** INNER(일치만), LEFT/RIGHT OUTER(한쪽 전체+NULL), FULL OUTER(양쪽 전체), CROSS(곱), SELF. 실무는 INNER·LEFT를 가장 많이 사용.
12. **데드락이란? 어떻게 해결하는가?** 트랜잭션들이 서로의 락 해제를 순환 대기. 예방(락 순서 고정·타임아웃), 탐지 후 victim 롤백. 대부분 DBMS가 데드락 탐지기 내장.
13. **락의 종류와 2PL이란?** 공유 락(읽기)·배타 락(쓰기). 2PL은 확장 단계(획득)+수축 단계(해제)로 직렬성 보장하는 비관적 제어.
14. **샤딩과 레플리케이션의 차이는?** 레플리케이션은 같은 데이터 복제(읽기 분산·가용성), 샤딩은 데이터 분할 저장(쓰기·용량 확장). 함께 쓰이기도 함.
15. **CAP 정리를 설명하라.** C·A·P 중 둘만 가능. P는 필수이므로 분할 시 일관성(CP, 일부 거부) 또는 가용성(AP, 최신성 미보장) 선택. 많은 NoSQL은 AP+최종 일관성.
16. **(심화) MySQL InnoDB가 REPEATABLE READ에서도 팬텀을 막는 이유는?** 갭 락·넥스트 키 락으로 조회 범위에 새 행 삽입을 차단하므로 표준보다 강하게 팬텀을 억제.

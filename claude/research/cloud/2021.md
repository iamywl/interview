## 2021 · 클라우드 · 쿠버네티스 · DevOps

### 1. 그해 핵심 트렌드
- 코로나19로 인한 비대면 전환과 디지털 트랜스포메이션이 가속되며 퍼블릭 클라우드 수요가 폭증한 해. 3대 하이퍼스케일러(AWS·Azure·GCP)가 모두 30~50%대 고성장을 기록했다.
- 쿠버네티스가 "사실상의 표준" 컨테이너 오케스트레이터로 자리 잡았고, 사용 형태는 자체 구축보다 매니지드 서비스(EKS·AKS·GKE) 중심으로 굳어졌다.
- 쿠버네티스 1.20에서 dockershim(도커 런타임 연동 모듈) 사용 중단(deprecation)이 예고되며 containerd·CRI-O로의 런타임 전환이 업계 화두가 됐다.
- GitOps가 엔터프라이즈 운영 방식으로 확산. Argo CD·Flux가 CNCF 인큐베이팅 단계로 올라서며 플랫폼 엔지니어링 실천의 핵심 축이 됐다.
- 연말 Log4Shell(CVE-2021-44228) 사태로 클라우드·컨테이너 환경의 소프트웨어 공급망 보안이 최우선 과제로 부상했다.

### 2. 대표 뉴스·사건
- 쿠버네티스 1.20이 dockershim 사용 중단을 공식 예고. 컨테이너 이미지 자체는 그대로 동작하지만, 노드 런타임은 containerd·CRI-O로 전환이 필요해졌다 ([Kubernetes Blog, 2020-12-02](https://kubernetes.io/blog/2020/12/02/dockershim-faq/)).
- Mirantis와 Docker가 dockershim을 쿠버네티스 외부 독립 컴포넌트로 유지·관리하기로 합의해, 도커 엔진을 계속 쓰려는 사용자에게 이행 경로를 제공했다 ([Mirantis, 2020-12-03](https://www.mirantis.com/blog/mirantis-to-take-over-support-of-kubernetes-dockershim-2/)).
- Argo CD·Flux 등 GitOps 도구가 엔터프라이즈 운영에서 본격 확산. CNCF 설문에서 응답자의 약 50%가 Argo CD를 사용·검토 중이라고 답했고, 플랫폼 엔지니어링 성장과 맞물렸다 ([The New Stack, 2021](https://thenewstack.io/survey-argocd-leaves-flux-and-other-gitops-platforms-behind/)).
- Microsoft가 Flux 기반 Azure GitOps를 6월 출시하는 등 하이퍼스케일러가 GitOps를 표준 기능으로 흡수했다 ([TechTarget, 2021](https://www.techtarget.com/searchitoperations/news/252528152/GitOps-hits-stride-as-CNCF-graduates-Flux-CD-and-Argo-CD)).
- 12월 Log4Shell(CVE-2021-44228) 제로데이가 공개. Apache가 CVSS 최고점 10.0을 부여했고, 디스클로저 10일 후에도 클라우드 환경의 취약 워크로드는 평균 45%만 패치된 상태였다 ([Wikipedia, Log4Shell](https://en.wikipedia.org/wiki/Log4Shell), [CISA, 2021-12-22](https://www.cisa.gov/news-events/cybersecurity-advisories/aa21-356a)).
- Google Cloud 2021년 2분기 매출이 전년 동기 대비 약 54% 증가한 46억 달러를 기록하며 연 180억 달러 매출 궤도에 올랐다 ([Holori, 2021](https://holori.com/2021-cloud-market-size-and-aws-azure-gcp-market-share/)).

### 3. 핵심 기업·제품·기술 키워드
- 하이퍼스케일러: AWS(EKS·Fargate·Lambda), Microsoft Azure(AKS), Google Cloud(GKE).
- 쿠버네티스 생태계: containerd, CRI-O, dockershim deprecation, Helm.
- GitOps·CD: Argo CD, Flux(2021년 CNCF 인큐베이션).
- 보안: Log4Shell(CVE-2021-44228), 소프트웨어 공급망 보안, Falco(런타임 위협 탐지, 2020년 CNCF 인큐베이터).
- CNCF·관측: Prometheus, KubeCon + CloudNativeCon.

### 4. 시장 수치·전망 (전망/추정 표기)
- 2021년 퍼블릭 클라우드 서비스 매출은 약 3,430억 달러로 추정(2022년 4,150억 달러로 증가) ([Holori, 2022](https://holori.com/cloud-market-2022/)).
- 2021년 시장 점유율(추정): AWS 약 33~37%, Azure 약 22~23%, GCP 약 9%. 3사 합계 약 66% ([Holori, 2021](https://holori.com/2021-cloud-market-size-and-aws-azure-gcp-market-share/)).
- Datadog 보고서 기준 쿠버네티스 사용자의 약 90%가 클라우드 매니지드 서비스를 활용(추정) ([opennaru, CNCF 정리](http://www.opennaru.com/kubernetes/cloud-native-computing-foundation-cncf/)).
- Log4Shell 발견 당시 전체 클라우드 환경의 약 93%가 위험에 노출(추정) ([Wikipedia, Log4Shell](https://en.wikipedia.org/wiki/Log4Shell)).

### 5. 전년 대비 변화점
- 새로 뜬 것: GitOps의 엔터프라이즈 본격 채택, dockershim deprecation에 따른 containerd 전환 논의, 소프트웨어 공급망 보안(Log4Shell 계기).
- 식은 것: 쿠버네티스 노드 런타임으로서의 도커 엔진 직접 의존. "쿠버네티스가 도커를 버린다"는 오해가 퍼졌으나 실제로는 런타임 연동 계층(dockershim)만 정리 대상이었다.

### 6. PT 발표 주제 후보
- "쿠버네티스는 왜 도커를 떠나는가": dockershim deprecation의 진짜 의미와 CRI·containerd 전환 — 오해와 사실을 구분하는 발표.
- "GitOps, 운영을 코드로": Argo CD·Flux로 선언형 배포를 구현하면 변경 추적과 롤백이 Git 이력으로 통합된다.
- "Log4Shell이 남긴 숙제": 컨테이너 환경에서 공급망 보안과 런타임 탐지가 왜 함께 필요한가.

### 7. 예상 꼬리질문 + 답변 포인트
- Q: dockershim이 제거되면 도커로 만든 이미지를 못 쓰나요?
  - A: 아닙니다. 변경 대상은 kubelet과 도커 엔진을 잇던 dockershim 연동 계층이고, OCI 표준 이미지 자체는 그대로 동작합니다. 노드 런타임만 containerd·CRI-O로 바뀝니다. 저는 컨테이너 보안을 공부하며 런타임이 시스템 콜을 통해 커널과 상호작용하는 구조를 다뤄봐서, CRI 추상화가 런타임 교체를 가능하게 하는 원리를 설명할 수 있습니다.
- Q: Log4Shell 같은 취약점을 컨테이너 환경에서 어떻게 탐지·대응하나요?
  - A: 배포 전에는 SBOM·이미지 스캔으로 취약 의존성을 식별하고, 런타임에는 비정상 행위를 잡아야 합니다. 저는 시스템 콜을 동적으로 관측해 이상 행위를 탐지하는 작업을 해봤는데, Log4Shell처럼 외부 LDAP 연결을 유발하는 익스플로잇은 예기치 않은 네트워크·프로세스 시스템 콜 패턴으로 드러나므로 커널 레벨 관측이 효과적입니다.
- Q: GitOps가 기존 CI/CD와 무엇이 다른가요?
  - A: Git 저장소를 단일 진실 공급원으로 삼아 클러스터의 실제 상태를 선언형 목표 상태로 지속 수렴시킨다는 점이 핵심입니다. 모든 변경이 Git 이력에 남아 감사·롤백이 쉽고, 권한도 Git 워크플로로 통제됩니다. 풀스택으로 확장하려는 입장에서 배포 파이프라인을 코드로 다루는 역량은 개발과 운영을 잇는 기반이 된다고 봅니다.

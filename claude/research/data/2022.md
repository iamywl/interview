## 2022 · 데이터 · 빅데이터 · 벡터DB

### 1. 한눈에 보기
2022년은 데이터 플랫폼 시장이 성숙기에 접어들며 Snowflake와 Databricks의 경쟁이 심화된 해였습니다. 이와 동시에 데이터의 양과 복잡성이 폭증하며 신뢰할 수 있는 데이터 활용을 위한 '데이터 거버넌스'가 핵심 화두로 떠올랐습니다. 연말 ChatGPT가 등장하기 전까지, 벡터DB는 비정형 데이터의 의미 기반 검색이라는 새로운 가능성을 품고 조용히 기반 기술을 다지며 전환점을 맞이하고 있었습니다.

### 2. 그해 핵심 트렌드
*   데이터 플랫폼 시장의 양강 구도: Snowflake와 Databricks가 데이터 웨어하우스와 데이터 레이크하우스 영역에서 서로의 영토를 확장하며 치열한 경쟁을 펼쳤습니다.
*   데이터 거버넌스의 부상: 데이터 품질, 보안, 규제 준수를 위한 체계적인 데이터 관리의 중요성이 대두되었고, OECD 등 국제기구에서도 정책 의제로 다루기 시작했습니다.
*   비정형 데이터 관리의 확장: 기업의 데이터 거버넌스가 기존의 정형 데이터를 넘어 이미지, 텍스트 등 비정형·반정형 데이터까지 포괄하는 방향으로 확대되었습니다.
*   벡터DB의 성장: AI 모델의 발달과 함께 의미 기반 검색의 필요성이 커지면서, Weaviate, Pinecone 등의 벡터DB 전문 기업들이 투자를 유치하며 기술 기반을 다졌습니다.
*   레이크하우스 아키텍처의 확산: 데이터 레이크의 유연성과 데이터 웨어하우스의 관리 기능을 결합한 '데이터 레이크하우스'가 데이터 아키텍처의 새로운 표준으로 주목받았습니다.
*   RAG 시대의 서막: 11월 ChatGPT 출시 이후, LLM의 한계(최신성 부족, 환각)를 보완하기 위한 RAG(검색증강생성)와 LangChain 같은 기술들이 개발자 커뮤니티에서 빠르게 주목받기 시작했습니다.

### 3. 대표 뉴스·사건
*   Weaviate가 2022년 4월 시리즈 B 5,000만 달러를 유치하며, 오픈소스 다운로드 200만 건을 돌파하며 벡터 검색 인프라 확장의 기틀을 마련했습니다 (Pinecone, 2023, [https://www.pinecone.io/lp/weaviate/](https://www.pinecone.io/lp/weaviate/)).
*   Snowflake는 2022년 매출 20억 달러 돌파가 전망되며, 전년 대비 60% 이상의 높은 성장률로 데이터 플랫폼 시장의 견고한 성장을 입증했습니다 (SaaStr, 2022, [https://www.saastr.com/databricks-vs-snowflake-at-5b-arr-same-revenue-2x-valuation-gap-heres-why/](https://www.saastr.com/databricks-vs-snowflake-at-5b-arr-same-revenue-2x-valuation-gap-heres-why/)).
*   Databricks는 데이터 사이언스 분야에서의 강점을 바탕으로 데이터 웨어하우스 시장으로, Snowflake는 데이터 웨어하우스에서 데이터 레이크 및 사이언스 영역으로 확장하며 약 200억 달러 규모의 데이터 시장에서 직접적인 경쟁 구도를 심화했습니다 (Wing VC, 2022, [https://www.wing.vc/content/comparing-the-financials-of-databricks-and-snowflake](https://www.wing.vc/content/comparing-the-financials-of-databricks-and-snowflake)).
*   OECD는 2022년 "성장과 복지를 위한 데이터 거버넌스"라는 종합 보고서 및 정책 형성 가이드를 발간하여, 데이터 거버넌스의 중요성을 국제 정책 의제로서 강조했습니다 (주OECD 대한민국 대표부, 2022, [https://overseas.mofa.go.kr/oecd-ko/brd/m_20806/view.do?seq=402&page=1&srchFr=&srchTo=&srchTp=0&srchWord=](https://overseas.mofa.go.kr/oecd-ko/brd/m_20806/view.do?seq=402&page=1&srchFr=&srchTo=&srchTp=0&srchWord=)).
*   2022년 11월 ChatGPT 출시 직후, 대규모 언어 모델(LLM)이 최신 정보나 내부 데이터를 학습하지 않았다는 한계가 부각되며, 이를 보완하기 위한 RAG(검색증강생성) 접근 방식과 LangChain 프레임워크가 빠르게 주목받기 시작했습니다 (Towards Data Science, 2022, [https://towardsdatascience.com/hitchhikers-guide-to-rag-with-chatgpt-api-and-langchain/](https://towardsdatascience.com/hitchhikers-guide-to-rag-with-chatgpt-api-and-langchain/)).
*   기업 데이터 거버넌스가 기존의 정형 데이터 관리 중심에서 Hadoop·Spark 기반 빅데이터 환경의 정형, 비정형, 반정형 데이터를 모두 포괄하는 방향으로 범위가 확장되었습니다 (Databricks, 2022, [https://www.databricks.com/discover/data-governance](https://www.databricks.com/discover/data-governance)).

### 4. 신기술 개념설명
#### 벡터DB (Vector Database)
*   **(1) 한 줄 정의:** 텍스트, 이미지 등 비정형 데이터를 AI가 이해하는 숫자 배열(벡터)로 변환해 저장하고, 데이터 간 의미적 유사성을 기준으로 검색하는 데 특화된 데이터베이스입니다.
*   **(2) 왜 나왔나:** 기존 관계형 데이터베이스는 'apple'이라는 정확한 단어가 포함된 문서는 잘 찾지만, '잘 익은 빨간 과일'처럼 의미는 같지만 표현이 다른 데이터는 찾지 못했습니다. AI 기술이 발전하면서 '이 이미지와 비슷한 분위기의 그림 찾기'처럼, 키워드가 아닌 '의미'를 기반으로 검색하려는 수요가 폭발적으로 증가하면서 기존 DB의 한계를 극복하기 위해 등장했습니다.
*   **(3) 어떻게 동작하나:** 먼저 AI 임베딩 모델을 사용해 모든 데이터(텍스트, 이미지 등)를 고차원 공간의 한 점을 나타내는 벡터(예: 384차원의 숫자 배열)로 변환합니다. 이때 의미가 비슷한 데이터들은 벡터 공간상에서 서로 가까운 위치에 놓이게 됩니다. 사용자가 검색 쿼리를 입력하면, 이 쿼리 역시 벡터로 변환한 뒤 '근사 최근접 이웃(ANN, Approximate Nearest Neighbor)' 같은 알고리즘을 사용해 벡터 공간에서 가장 가까운 거리에 있는 데이터 벡터들을 매우 빠른 속도로 찾아내 결과를 돌려줍니다.
*   **(4) 무엇이 달라지나:** 키워드가 일치해야만 가능했던 검색의 패러다임을 '의미' 기반으로 바꾸었습니다. 이를 통해 추천 시스템의 정확도를 높이고, 이미지나 음성으로 검색하는 등 새로운 사용자 경험을 만들 수 있게 됐습니다. 다만, ANN 알고리즘은 정확한 값이 아닌 '근사값'을 찾기 때문에 100% 정확한 결과를 보장하지 않을 수 있다는 한계도 있습니다.

#### 데이터 거버넌스 (Data Governance)
*   **(1) 한 줄 정의:** 데이터의 생성부터 활용, 폐기까지 전 과정에 걸쳐 데이터의 품질과 보안, 접근성을 보장하기 위한 정책, 프로세스, 기술을 총망라하는 관리 체계입니다.
*   **(2) 왜 나왔나:** 기업에 데이터는 폭발적으로 쌓이지만, 어디에 어떤 데이터가 있는지 모르고 품질도 낮아 활용하지 못하는 '데이터 사일로' 문제가 심각해졌습니다. 또한 GDPR, 데이터 3법 등 국내외 규제가 강화되면서, 데이터를 체계적으로 관리하고 보호하지 않으면 법적, 재정적 리스크에 직면하게 되었습니다. 신뢰할 수 있는 데이터 기반의 의사결정을 위해 전사적인 관리 체계가 필수가 된 것입니다.
*   **(3) 어떻게 동작하나:** 먼저 데이터 표준화, 데이터 품질 측정, 데이터 소유권 정의 등 데이터 관리를 위한 '규칙'을 만듭니다. 그리고 '데이터 카탈로그'를 구축해 데이터의 위치, 의미, 소유자 등의 정보를 등록하여 누구나 쉽게 데이터를 찾고 이해할 수 있게 합니다. 또한 '데이터 계보(Data Lineage)' 추적을 통해 데이터가 어디서 와서 어떻게 변경되었는지 전체 흐름을 파악하고, 직무에 따라 데이터 접근 권한을 차등 부여하여 보안을 강화합니다.
*   **(4) 무엇이 달라지나:** 데이터가 더 이상 IT 부서의 전유물이 아닌, 전사적인 '자산'으로 인식하게 됩니다. 데이터 분석가는 신뢰할 수 있는 데이터를 찾아 헤매는 시간을 줄이고 분석 본연의 업무에 집중할 수 있게 됩니다. 기업은 데이터 기반의 정확한 의사결정을 내리고, 데이터 관련 규제 리스크를 최소화하여 비즈니스 경쟁력을 높일 수 있습니다.

### 5. 핵심 기업·제품·기술 키워드
*   **기업/제품:** Snowflake, Databricks (Unity Catalog), Confluent, Weaviate, Pinecone, Qdrant, Milvus
*   **데이터 플랫폼:** 데이터 레이크하우스(Data Lakehouse), 데이터 웨어하우스(Data Warehouse), 데이터 메시(Data Mesh)
*   **데이터 거버넌스:** 데이터 품질, 데이터 계보(Lineage), 접근 통제, 규제 준수, 데이터 카탈로그, Unity Catalog, Apache Atlas
*   **신흥 키워드 (연말):** RAG(검색증강생성), 임베딩(Embedding), 벡터 검색, LangChain, LlamaIndex, LLM
*   **테이블 포맷:** Delta Lake, Apache Iceberg, Apache Hudi
*   **데이터 스트리밍:** Apache Kafka, Flink

### 6. 시장 수치·전망
*   **Snowflake:** 2022년 매출 약 20억 달러 돌파가 전망되었고, 전년 대비 60% 이상의 높은 성장률을 기록하며 데이터 클라우드 시장을 선도했습니다. (SaaStr, 2022, [https://www.saastr.com/databricks-vs-snowflake-at-5b-arr-same-revenue-2x-valuation-gap-heres-why/](https://www.saastr.com/databricks-vs-snowflake-at-5b-arr-same-revenue-2x-valuation-gap-heres-why/)).
*   **Databricks:** 2022년 무렵 연간 반복 매출(ARR) 10억 달러를 돌파한 것으로 추정되며, 데이터 레이크하우스 아키텍처를 중심으로 빠른 성장을 이어갔습니다. (SaaStr, 2022, [https://www.saastr.com/databricks-vs-snowflake-at-5b-arr-same-revenue-2x-valuation-gap-heres-why/](https://www.saastr.com/databricks-vs-snowflake-at-5b-arr-same-revenue-2x-valuation-gap-heres-why/)).
*   **전체 데이터 시장 규모:** 2022년 기준 200억 달러 이상으로 추정되며, 클라우드 기반 데이터 플랫폼의 성장이 시장 확대를 견인했습니다. (SaaStr, 2022, [https://www.saastr.com/databricks-vs-snowflake-at-5b-arr-same-revenue-2x-valuation-gap-heres-why/](https://www.saastr.com/databricks-vs-snowflake-at-5b-arr-same-revenue-2x-valuation-gap-heres-why/)).
*   **Weaviate:** 2022년 시리즈 B에서 5,000만 달러를 유치해 누적 투자액 6,700만 달러를 기록하며, 벡터DB 분야의 선두 주자 중 하나로 성장 잠재력을 인정받았습니다. (Pinecone, 2023, [https://www.pinecone.io/lp/weaviate/](https://www.pinecone.io/lp/weaviate/)).

### 7. 전년 대비 변화점
*   **새로 뜬 것:**
    *   **RAG & LLM 생태계:** 2022년 말, ChatGPT의 등장과 함께 RAG, 임베딩, 벡터 검색, LangChain 같은 기술들이 LLM의 한계를 극복할 현실적 대안으로 급부상하며 새로운 기술 패러다임의 서막을 열었습니다.
    *   **데이터 거버넌스의 제도화:** OECD의 정책 가이드 발표와 Databricks Unity Catalog 같은 통합 솔루션의 등장은, 데이터 거버넌스가 일부 기업의 과제를 넘어 국제적 표준이자 필수적인 기술 아젠다로 자리 잡았음을 보여줍니다.

*   **강화된 것:**
    *   **데이터 플랫폼 양강 구도:** Snowflake와 Databricks의 경쟁은 더욱 치열해졌습니다. 이들은 서로의 핵심 영역으로 기능을 확장하며 데이터 웨어하우스와 데이터 레이크의 경계를 허무는 '레이크하우스'로의 수렴을 가속화했습니다.
    *   **클라우드 네이티브 전환:** 클라우드 기반 데이터 플랫폼의 성장세가 더욱 견고해지며, 기업들이 온프레미스 솔루션에서 클라우드 네이티브 아키텍처로 전환하는 추세가 더욱 명확해졌습니다.

*   **식기 시작한 것:**
    *   **틈새 기술로서의 벡터DB:** 2022년 이전까지 벡터DB는 특정 AI/ML 용도에 국한된 기술로 여겨졌습니다. 하지만 연말 LLM의 부상과 함께 RAG의 핵심 인프라로 주목받으며, '틈새'를 넘어 '필수' 기술로 위상이 급격히 변화하기 시작한 전환점이었습니다.

### 8. PT 발표 주제 후보
*   **"데이터 거버넌스, 디지털 신뢰의 핵심 기반"**
    *   **한 줄 메시지:** 데이터 폭증 시대, 거버넌스는 단순한 규제가 아닌 기업 경쟁력과 디지털 신뢰를 확보하는 필수 전략입니다.
    *   **발표 3단 구조:**
        *   **문제(Problem):** 데이터는 많지만 쓸 수 없는 '데이터 사일로', 품질 저하, 규제 리스크 증가 문제를 지적합니다.
        *   **근거(Solution):** OECD 보고서와 Unity Catalog 등 통합 플랫폼 등장을 근거로 거버넌스의 중요성을 강조하며 데이터 계보, 품질 관리 등 기술적 구현 방안을 제시합니다.
        *   **제언(Impact):** 체계적인 거버넌스 구축이 어떻게 신뢰 기반의 데이터 혁신과 비즈니스 가치 창출로 이어지는지 제언합니다.

*   **"ChatGPT가 연 RAG 시대: LLM의 한계를 넘어 실용적 AI로"**
    *   **한 줄 메시지:** LLM의 환각 문제를 검색증강생성(RAG)과 벡터DB가 어떻게 극복하고 실용적인 AI 시대를 열었는지 조명합니다.
    *   **발표 3단 구조:**
        *   **문제(Problem):** LLM의 최신 정보 부족과 환각 현상으로 인한 비즈니스 적용의 어려움을 제시합니다.
        *   **근거(Solution):** RAG의 개념과 동작 원리를 벡터DB와의 연관성 속에서 설명하며 기술적 우위를 부각합니다.
        *   **제언(Impact):** RAG 기반 질의응답 시스템 등 구체적인 활용 사례를 통해 기업의 생산성을 어떻게 향상시킬 수 있는지 제언합니다.

*   **"데이터 플랫폼 전쟁: Snowflake vs Databricks, 통합 아키텍처를 향한 경쟁"**
    *   **한 줄 메시지:** 데이터 웨어하우스와 데이터 레이크하우스의 경계가 허물어지는 가운데, 두 거인이 펼치는 시장 주도권 경쟁의 의미와 미래를 분석합니다.
    *   **발표 3단 구조:**
        *   **문제(Problem):** 데이터 분석 환경의 복잡성 증가와 데이터 저장소 간의 비효율성을 지적합니다.
        *   **근거(Solution):** Snowflake와 Databricks의 성장과 상호 영역 확장 전략을 분석하며, '레이크하우스' 아키텍처가 왜 이 경쟁의 중심에 있는지 기술적으로 설명합니다.
        *   **제언(Impact):** 통합 데이터 플랫폼이 기업의 데이터 전략에 주는 의미를 설명하고, 향후 모든 데이터를 한 곳에서 처리하는 아키텍처의 중요성을 강조하며 마무리합니다.

### 9. 예상 질문 + 모범답안
#### 1. 데이터 거버넌스에서 데이터 계보(Lineage)가 왜 중요하며, 본인의 경험과 관련지어 설명해본다면?
네, 데이터 계보는 데이터의 신뢰도를 보증하고 문제 발생 시 원인을 빠르게 파악할 수 있게 해주는 '족보'와 같기 때문에 매우 중요합니다. 저는 컨테이너 환경에서 시스템 콜의 흐름을 동적으로 관측하여 비정상 행위를 탐지하는 프로젝트를 수행한 경험이 있습니다. 이때 어떤 프로세스가 어떤 시스템 콜을 순서대로 호출했는지 그 '계보'를 추적하는 것이 이상 행위의 근원을 찾는 데 결정적이었습니다. 데이터 계보도 마찬가지로, 데이터가 어떤 원천에서 생성되어 어떤 변환 과정을 거쳐 현재의 분석에 사용되었는지 그 흐름을 추적할 수 있어야만 데이터의 신뢰성을 담보하고, 분석 결과에 오류가 발생했을 때 근본 원인을 찾아 해결할 수 있다고 생각합니다.

#### 2. 데이터 품질 문제를 탐지하고 개선하기 위해 자신의 '이상탐지' 프로젝트 경험을 어떻게 적용할 수 있을까요?
제가 수행했던 시스템 콜 기반 이상탐지 모델의 핵심 원리를 데이터 품질 관리에 적용할 수 있습니다. 먼저, 정상 상태의 데이터가 가진 통계적 패턴을 '프로파일'로 학습합니다. 예를 들어, 특정 컬럼의 값 범위, 분포, 데이터 형식, 다른 데이터와의 상관관계 등을 정상 상태의 기준으로 정의하는 것입니다. 그 후, 새로 유입되거나 변경되는 데이터가 이 프로파일에서 통계적으로 유의미하게 벗어나는 '이상 징후'를 보일 때 이를 탐지하여 경고를 보낼 수 있습니다. 이는 마치 제가 정상적인 시스템 콜의 패턴을 벗어나는 호출을 탐지했던 것과 동일한 접근 방식입니다. 이런 자동화된 모니터링 시스템을 통해 데이터 품질 저하를 조기에 발견하고 선제적으로 대응할 수 있을 것입니다.

#### 3. RAG, 임베딩, 벡터DB 세 가지 기술의 관계를 비전공자도 이해하기 쉽게 설명해 보세요.
네, 세 기술은 '유능한 전문 비서'를 만드는 데 필요한 핵심 도구 세트라고 할 수 있습니다. 먼저 **임베딩**은 세상의 모든 정보를 컴퓨터가 이해할 수 있는 고유한 '숫자 좌표'로 바꿔주는 기술입니다. '사과'와 '배'는 비슷한 과일이니 좌표 공간에서 가까운 곳에, '자동차'는 전혀 다르니 아주 먼 곳에 배치하는 식입니다. **벡터DB**는 이렇게 만들어진 수많은 좌표들을 효율적으로 저장하고 검색할 수 있는 특별한 '디지털 도서관'입니다. 마지막으로 **RAG**는 이 도서관을 활용해 비서가 똑똑하게 일하는 '방식'입니다. 사용자가 질문을 하면, 비서는 먼저 질문의 핵심을 '좌표'로 변환해 도서관(벡터DB)에서 가장 관련 있는 자료들을 몇 초 만에 찾아옵니다. 그리고 그 자료들을 근거로 삼아 가장 정확하고 신뢰도 높은 답변을 생성해 사용자에게 전달하는 것입니다.

#### 4. SSAFY 프로젝트에서 RAG 기술을 활용한다면 어떤 서비스를 만들고 싶고, 왜 그렇게 생각하나요?
SSAFY에서 Python과 Django를 배우게 되는 만큼, 이를 활용하여 'SSAFY 교육 과정 맞춤형 Q&A 챗봇'을 만들어보고 싶습니다. 교육생들이 수많은 공지사항, 과제 요강, 생활 규칙 등을 일일이 찾아보는 불편함을 해소해주는 서비스입니다. Django로 백엔드 서버를 구축하고, LangChain 프레임워크를 이용해 RAG 파이프라인을 구현하겠습니다. 벡터DB는 초기 단계에서는 별도 서버 설치가 필요 없는 FAISS나 ChromaDB를 사용하여 빠르게 프로토타입을 개발하고, 기능이 안정되면 확장성을 고려해 다른 DB로 전환하는 경험도 해보고 싶습니다. 이 프로젝트는 단순히 기술을 사용하는 것을 넘어, 제가 가진 리눅스 커널과 시스템 동작 원리 이해를 바탕으로 각 오픈소스 도구들이 내부적으로 어떻게 동작하는지 분석하며 더 깊이 있는 학습을 할 좋은 기회라고 생각합니다. 이를 통해 서비스 구현 능력과 시스템 이해도를 모두 갖춘 '융합형 개발자'로 성장하는 발판을 마련하고 싶습니다.

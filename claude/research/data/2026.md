## 2026 · 데이터 · 빅데이터 · 벡터DB (1~6월)

### 1. 그해 핵심 트렌드
2026년 상반기 데이터 인프라의 화두는 "RAG 이후"와 "에이전트를 위한 데이터"다. 단순 벡터 검색만으로는 에이전트가 상태를 유지하고 학습하기에 부족하다는 인식이 퍼지면서, 컨텍스트 아키텍처·에이전트 메모리·GraphRAG가 단순 RAG를 보완·대체하는 흐름이 형성됐다. 모델과 데이터 소스를 표준 방식으로 연결하는 MCP(Model Context Protocol)가 "AI의 USB-C"로 불리며 사실상 표준으로 자리잡아, "벡터 인덱스 구축"보다 "데이터를 MCP로 노출"하는 것이 더 흔한 설계 결정이 되어가고 있다. 오픈 테이블 포맷 측면에선 Apache Iceberg v3가 Databricks에서 공개 미리보기에 들어가고 Apache Polaris가 프로덕션 수준으로 성숙하며 Iceberg가 레이크하우스 표준 계층으로 굳어졌다. Databricks는 12월 134억 달러 밸류에이션 위에서 2026년 IPO 가능성이 거론된다.

### 2. 대표 뉴스·사건
- Databricks가 Apache Iceberg v3를 공개 미리보기로 제공, 증분 데이터 처리·반정형 데이터 분석 등 그동안 우회책이 필요했던 사용 사례를 개방형 레이크하우스에서 네이티브로 지원하기 시작했다 ([Databricks Blog, 2026](https://www.databricks.com/blog/next-era-open-lakehouse-apache-icebergtm-v3-public-preview-databricks)).
- Oracle이 2026년 3월 24일 AI Database의 에이전트 혁신을 발표, 외부 AI 에이전트가 커스텀 연동 코드 없이 DB에 안전하게 접근하는 AI Database MCP Server를 선보였다 ([Oracle, 2026-03-24](https://www.oracle.com/news/announcement/oracle-unveils-ai-database-agentic-innovations-for-business-data-2026-03-24/)).
- 에이전틱 AI가 기업 검색을 한계까지 밀어붙이면서, 단순 RAG를 컨텍스트 아키텍처가 대체하는 흐름이 보도됐다. 검색 최적화 투자 비중이 19%에서 28.9%로, 하이브리드 검색 도입 의향은 1~3월 사이 10.3%에서 33.3%로 세 배 증가했다(조사 추정) ([VentureBeat, 2026](https://venturebeat.com/data/context-architecture-is-replacing-rag-as-agentic-ai-pushes-enterprise-retrieval-to-its-limits)).
- 2026년 데이터 예측에서 "RAG는 죽었다"는 도발적 화두와 함께, 벡터가 별도 DB 유형이 아니라 멀티모델 DB에 통합되는 데이터 타입이 되고 운영 에이전틱 AI에선 컨텍스트 메모리가 기본값이 될 것이란 전망이 제시됐다 ([VentureBeat, 2026](https://venturebeat.com/data/six-data-shifts-that-will-shape-enterprise-ai-in-2026)).
- MCP가 2026년 초 "AI의 USB-C"로 불리며 모델·데이터 소스 간 표준 통신 언어로 자리잡아, 2026년 말이면 "데이터를 MCP로 노출"이 "벡터 인덱스 구축"보다 흔한 결정이 될 것으로 전망됐다 ([VentureBeat, 2026](https://venturebeat.com/data/six-data-shifts-that-will-shape-enterprise-ai-in-2026)).
- Databricks가 2025년 12월 134억 달러 밸류에이션(매출 런레이트 약 48억 달러, 전년 대비 55% 성장)에 도달한 뒤, 2026년 IPO를 향한 행보로 시장의 관심을 받고 있다 ([CNBC, 2025-12-16](https://www.cnbc.com/2025/12/16/databricks-funding-valuation.html)).

### 3. 핵심 기업·제품·기술 키워드
- 검색/메모리: 컨텍스트 아키텍처, 에이전트 메모리, GraphRAG, 하이브리드 검색(키워드+벡터)
- 표준/프로토콜: MCP(Model Context Protocol), Iceberg REST Catalog, Apache Polaris
- 오픈 포맷: Apache Iceberg v3(공개 미리보기), Delta Lake, Apache Polaris(프로덕션화)
- 기업/제품: Databricks(Iceberg v3·IPO), Snowflake(Open Catalog), Oracle(AI Database MCP Server), Qdrant, Teradata 벡터 스토어

### 4. 시장 수치·전망
- 벡터DB 시장: 2028년까지 약 50억 달러 규모 전망 ([VentureBeat, 2026](https://venturebeat.com/data/six-data-shifts-that-will-shape-enterprise-ai-in-2026)).
- 검색 최적화 투자 비중: 19% → 28.9%로 상승, 하이브리드 검색 도입 의향 10.3% → 33.3%(1~3월, 조사 추정) ([VentureBeat, 2026](https://venturebeat.com/data/context-architecture-is-replacing-rag-as-agentic-ai-pushes-enterprise-retrieval-to-its-limits)).
- Databricks: 매출 런레이트 약 48억 달러(전년 대비 55% 성장 추정), 밸류에이션 134억 달러, 2026년 IPO 시 시가총액 1,500억~1,800억 달러 목표 전망(추정) ([CNBC, 2025-12-16](https://www.cnbc.com/2025/12/16/databricks-funding-valuation.html)).

### 5. 전년 대비 변화점
- 새로 뜬 것: "RAG 이후" 담론(컨텍스트 아키텍처·에이전트 메모리·GraphRAG). MCP가 사실상 표준 통신 계층으로 격상. Iceberg v3·Polaris 프로덕션화로 오픈 포맷 표준 정착.
- 강화된 것: 벡터가 별도 DB가 아니라 멀티모델 DB의 한 데이터 타입으로 흡수되는 흐름(2025년 시작 → 2026년 본격화).
- 식은 것: "전용 벡터DB 구축"의 절대성. 정적 데이터엔 RAG가 유효하나, 적응형 에이전트엔 메모리·컨텍스트가 우선시됨.

### 6. PT 발표 주제 후보
- "RAG 이후: 컨텍스트 아키텍처와 에이전트 메모리" — 단순 벡터 검색의 한계와 다음 패러다임.
- "MCP, AI의 USB-C" — 데이터 노출 표준이 벡터 인덱스 설계를 대체하는 흐름.
- "Iceberg가 표준이 된 레이크하우스" — v3·Polaris로 본 오픈 포맷의 제도화.

### 7. 예상 꼬리질문 + 답변 포인트
- Q: RAG의 한계가 무엇이기에 "RAG 이후"가 논의되나?
  A: RAG는 매 질의마다 관련 문서를 검색해 주입하는 무상태 방식이라, 정적 지식엔 강하지만 에이전트가 대화·작업의 상태를 기억하고 피드백으로 학습하기엔 부족하다. 그래서 에이전트 메모리(상태 유지)와 GraphRAG(관계 구조 활용), 컨텍스트 아키텍처가 보완책으로 부상한다. RAG가 사라지는 게 아니라 적용 범위가 정적 데이터로 좁혀지는 것이다.
- Q: MCP가 왜 "USB-C"로 불리나? 보안 관점에서 어떤가?
  A: 모델과 데이터 소스마다 제각각이던 연동을 표준 프로토콜 하나로 통일해 "USB-C"라 불린다. 다만 외부 에이전트가 표준 통로로 DB에 접근하는 만큼, 인증·인가·감사가 통로에 집중된다. 제가 다룬 컨테이너 보안·시스템 콜 관측의 관점에서 보면, MCP 서버는 새로운 신뢰 경계이자 접근 통제·관측 지점이라, 권한 최소화와 호출 감사가 보안 설계의 핵심이 된다.
- Q: 벡터가 별도 DB가 아니라 데이터 타입이 되면 벡터DB 기업은 어떻게 되나?
  A: PostgreSQL의 pgvector처럼 기존 DB가 벡터를 흡수하면, 단순 저장·검색만으로는 전용 벡터DB의 차별성이 줄어든다. 전용 기업은 초고규모·초저지연 검색, 하이브리드 검색, 에이전트 메모리 같은 상위 기능으로 차별화해야 한다. 인프라를 늘리기 전에 기존 스택으로 충분한지 보는 풀스택 판단이 더 중요해지는 국면이다.

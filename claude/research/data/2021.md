## 2021 · 데이터 · 빅데이터 · 벡터DB

### 1. 한눈에 보기
2021년은 클라우드 데이터 플랫폼이 시장의 주류로 완전히 자리 잡은 해였습니다. 데이터브릭스의 '레이크하우스'가 데이터웨어하우스와 데이터레이크의 해묵은 경쟁 구도를 통합하려는 시도로 주목받았고, 컨플루언트의 성공적인 상장은 '데이터 인 모션' 즉, 실시간 데이터 처리의 시대가 본격적으로 열렸음을 알렸습니다. 이와 함께 데이터 메시(Data Mesh)와 같은 분산형 아키텍처 논의가 시작되며 데이터 관리의 패러다임 전환을 예고했습니다.

### 2. 그해 핵심 트렌드
*   **클라우드 데이터 플랫폼의 완전한 주류화:** Snowflake와 Databricks가 클라우드 데이터 시장의 성장을 견인하며, 기업들의 데이터 인프라가 온프레미스에서 클라우드로 빠르게 전환되었습니다.
*   **'레이크하우스' 아키텍처의 대두:** 데이터 레이크의 유연함과 데이터 웨어하우스의 강력한 관리 기능을 통합하려는 '레이크하우스' 개념이 Databricks를 중심으로 큰 호응을 얻으며 새로운 아키텍처 표준으로 부상했습니다.
*   **'데이터 인 모션'의 가치 증명:** 실시간 데이터 스트리밍 플랫폼인 Confluent가 성공적으로 나스닥에 상장하면서, 데이터가 생성되는 즉시 처리하는 '스트리밍' 방식의 중요성이 시장에서 공식적으로 인정받았습니다.
*   **분산형 데이터 아키텍처 담론의 시작:** 모든 데이터를 중앙에서 관리하는 방식의 한계가 드러나면서, 데이터를 현업 부서가 직접 제품처럼 관리하는 '데이터 메시(Data Mesh)'와 같은 새로운 조직적, 기술적 접근법이 주목받기 시작했습니다.

### 3. 대표 뉴스·사건
*   Databricks가 2021년 2월 시리즈 G 라운드에서 10억 달러 투자를 유치하며 280억 달러의 기업 가치를 평가받았습니다. 이는 IPO 가능성을 높이고 경쟁사 Snowflake를 추격하려는 전략의 일환이었습니다. ([SiliconANGLE, 2021-02-01](https://siliconangle.com/2021/02/01/massive-1b-infusion-databricks-takes-aim-ipo-rival-snowflake/))
*   Confluent가 2021년 6월 24일 나스닥에 성공적으로 상장(티커 CFLT)했습니다. 주당 36달러에 2,300만 주를 공모하여 약 8억 2,800만 달러를 조달했으며, 첫 거래일 25% 급등하여 시가총액 약 114억 달러를 기록했습니다. ([CNBC, 2021-06-24](https://www.cnbc.com/2021/06/24/confluent-climbs-26percent-after-raising-828-million-in-ipo.html))
*   Confluent는 S-1 보고서에서 2,500개 이상의 고객사와 2021년 1분기 매출이 전년 대비 51% 성장했다고 발표하며, 잠재 시장(TAM)을 최대 500억 달러로 추정했습니다. 이는 Kafka 기반 이벤트 스트리밍 시장의 거대한 잠재력을 시사했습니다. ([TechTarget, 2021-06](https://www.techtarget.com/searchdatamanagement/news/252502989/Confluent-goes-IPO-as-Kafka-event-streaming-goes-mainstream))
*   Databricks는 2021년 후반 시리즈 H 펀딩에서 16억 달러를 추가 조달하며 기업 가치가 380억 달러로 상승했습니다. 이를 통해 Apache Spark를 기반으로 하는 통합 데이터 플랫폼 전략, 특히 레이크하우스 아키텍처 강화에 박차를 가했습니다. ([SiliconANGLE, 2021-02-01](https://siliconangle.com/2021/02/01/massive-1b-infusion-databricks-takes-aim-ipo-rival-snowflake/))
*   Databricks는 데이터 레이크의 스토리지 효율성과 데이터 웨어하우스의 데이터 관리 기능을 결합한 '레이크하우스' 아키텍처를 적극적으로 홍보하며, 오픈소스 프로젝트인 Delta Lake를 중심으로 ACID 트랜잭션, 스키마 적용 등의 기능을 제공했습니다. ([Databricks Blog, 2020-09-10](https://www.databricks.com/blog/2020/09/10/diving-deep-into-the-inner-workings-of-the-lakehouse-and-delta-lake.html))
*   Snowflake는 2018년 9,600만 달러였던 연 매출을 2021년 10억 달러 이상으로 성장시키며 클라우드 데이터 웨어하우스 시장을 선도했고, 나아가 '데이터 클라우드'라는 확장된 개념으로 시장 포지셔닝을 강화했습니다. ([Tietoevry, 2021-09](https://www.tietoevry.com/en/blog/2021/09/data-lakes-and-warehouses-databricks-snowflake/))

### 4. 신기술 개념설명
#### 데이터 레이크하우스 (Data Lakehouse)
*   **(1) 한 줄 정의:** 데이터 레이크의 저비용 유연성과 데이터 웨어하우스의 신뢰성 높은 관리 기능을 결합한 단일 데이터 관리 플랫폼입니다.
*   **(2) 왜 나왔나:** 과거에는 분석용 정형 데이터를 위한 웨어하우스와 모든 원시 데이터를 저장하는 레이크를 별도로 운영했습니다. 이로 인해 데이터가 중복 저장되고, 두 시스템 간 데이터를 옮기는 복잡한 파이프라인이 필요했으며, 결과적으로 관리 비용 증가와 분석 지연 문제가 발생했습니다.
*   **(3) 어떻게 동작하나:** 기본 구조는 S3나 ADLS Gen2 같은 저비용 객체 스토리지(데이터 레이크)입니다. 그 위에 '델타 레이크(Delta Lake)'나 '아파치 아이스버그(Apache Iceberg)' 같은 오픈소스 테이블 포맷을 적용하여, ACID 트랜잭션, 데이터 버전 관리, 스키마 강제와 같은 데이터 웨어하우스의 핵심 기능들을 구현합니다.
*   **(4) 무엇이 달라지나:** 데이터 파이프라인이 극적으로 단순화됩니다. 데이터 분석가와 AI/ML 엔지니어는 더 이상 데이터 사일로를 걱정할 필요 없이, 하나의 플랫폼에서 신뢰할 수 있는 단일 데이터 소스를 사용해 BI 대시보드 작업과 머신러닝 모델 학습을 동시에 수행할 수 있게 됩니다.

#### 데이터 인 모션 (Data in Motion)
*   **(1) 한 줄 정의:** 데이터가 디스크에 저장된 후가 아니라, 생성되어 시스템 간에 흐르는 과정에서 실시간으로 처리하고 분석하는 개념입니다.
*   **(2) 왜 나왔나:** 하루나 한 시간 단위로 데이터를 모아서 처리하는 전통적인 '배치(Batch)' 방식으로는 실시간 상품 추천, 금융 사기 탐지, 스마트팩토리 설비 이상 감지처럼 즉각적인 반응이 필요한 비즈니스 요구를 충족시킬 수 없었습니다.
*   **(3) 어떻게 동작하나:** 아파치 카프카(Apache Kafka)와 같은 이벤트 스트리밍 플랫폼이 데이터가 발생하는 즉시 '이벤트 스트림' 형태로 수집합니다. 이 데이터는 데이터베이스에 저장되기 전에 Flink나 Spark Streaming 같은 처리 엔진을 통해 실시간으로 분석, 필터링, 강화된 후, 즉시 필요한 시스템(예: 대시보드, 경고 시스템)으로 전달됩니다.
*   **(4) 무엇이 달라지나:** 기업이 과거 데이터를 분석하여 사후에 대응하는 '수동적'인 자세에서 벗어나, 현재 일어나는 일을 즉시 파악하고 미래를 예측하여 '능동적'으로 대응할 수 있게 됩니다. 이는 비즈니스 의사결정의 속도와 질을 근본적으로 바꾸는 변화입니다.

### 5. 핵심 기업·제품·기술 키워드
*   **기업/제품:** Snowflake(데이터 클라우드), Databricks(레이크하우스, Delta Lake), Confluent(Apache Kafka, data in motion)
*   **테이블 포맷:** Delta Lake, Apache Iceberg, Apache Hudi
*   **아키텍처/개념:** 레이크하우스, 데이터 메시, 데이터 패브릭, 데이터 인 모션(Data in Motion), 스트리밍/이벤트 처리
*   **처리 엔진:** Apache Spark, Apache Flink, Trino(구 PrestoSQL)

### 6. 시장 수치·전망
*   **Snowflake:** 2021년에 연 매출 10억 달러를 돌파했으며, 2022년에는 20억 달러 돌파가 전망되었습니다(전년 대비 60%+ 성장 추정). 이는 클라우드 데이터 웨어하우스 및 데이터 클라우드 시장의 폭발적인 성장을 반영합니다. ([Tietoevry, 2021-09](https://www.tietoevry.com/en/blog/2021/09/data-lakes-and-warehouses-databricks-snowflake/))
*   **Databricks:** 2021년 시리즈 H 투자 유치 당시 기업 가치는 380억 달러로 평가되었습니다. 이는 레이크하우스 아키텍처와 통합 데이터 플랫폼에 대한 시장의 높은 기대를 보여줍니다. ([SiliconANGLE, 2021-02-01](https://siliconangle.com/2021/02/01/massive-1b-infusion-databricks-takes-aim-ipo-rival-snowflake/))
*   **Confluent:** 2021년 상장 시 시가총액은 약 114억 달러를 기록했으며, 잠재 시장(TAM) 규모를 최대 500억 달러로 추정했습니다. 이는 Apache Kafka를 중심으로 하는 실시간 데이터 스트리밍 및 이벤트 처리 시장이 거대한 성장 잠재력을 가지고 있음을 의미합니다. ([TechTarget, 2021-06](https://www.techtarget.com/searchdatamanagement/news/252502989/Confluent-goes-IPO-as-Kafka-event-streaming-goes-mainstream))

### 7. 전년 대비 변화점
*   **새로 뜬 것:**
    *   **레이크하우스의 대중화:** 단순한 마케팅 용어를 넘어, 실제 기업들이 데이터 레이크와 웨어하우스를 통합하는 아키텍처로 레이크하우스를 적극적으로 도입하기 시작했습니다.
    *   **스트리밍 데이터 시장의 독립:** Confluent의 성공적인 상장을 계기로, 실시간 데이터 스트리밍이 독립적인 IT 시장 카테고리로 확고히 인정받았습니다.
    *   **데이터 거버넌스 및 조직 혁신 담론 부상:** 데이터 메시와 데이터 패브릭처럼, 데이터 관리의 기술적 측면과 조직적 측면을 아우르는 새로운 개념들이 주요 논제로 떠올랐습니다.
*   **식은 것:**
    *   **온프레미스 Hadoop 중심 빅데이터의 퇴조:** 과거 빅데이터의 대명사였던 온프레미스 Hadoop 기반 솔루션의 매력도가 급감하고, 클라우드 네이티브 데이터 플랫폼으로의 전환이 가속화되었습니다.
*   **아직 없던 것:**
    *   **벡터DB 및 RAG의 부재:** 생성형 AI 기술이 본격적으로 부상하기 전이므로, 비정형 데이터의 의미 기반 검색을 위한 벡터 데이터베이스와 검색 증강 생성(RAG)은 2021년에는 주류 키워드가 아니었으며, 2022년 하반기와 2023년에 걸쳐 크게 부상하게 됩니다.

### 8. PT 발표 주제 후보
*   **주제 1: "레이크하우스, 데이터 사일로를 허무는 통합의 아키텍처"**
    *   **한 줄 메시지:** 데이터 레이크와 웨어하우스의 장점만을 결합해 데이터 분석 환경을 혁신하는 레이크하우스 아키텍처의 부상과 그 의미를 설명합니다.
    *   **발표 3단 구조:**
        *   **문제:** 데이터 웨어하우스와 레이크의 이원화는 데이터 중복, 관리 복잡성, 분석 지연이라는 고질적인 문제를 낳았습니다.
        *   **근거:** 레이크하우스는 단일 저장소에서 BI와 AI 워크로드를 모두 지원하여 데이터 파이프라인을 단순화하고, 데이터 신뢰성과 유연성을 동시에 확보합니다. (Databricks, Delta Lake 사례)
        *   **제언:** 기업은 데이터의 민주적 활용과 신속한 의사결정을 위해, 기존 데이터 인프라를 레이크하우스 아키텍처로 전환하는 것을 적극 검토해야 합니다.

*   **주제 2: "데이터 인 모션(Data in Motion): 실시간 데이터가 기업의 경쟁력이다"**
    *   **한 줄 메시지:** Confluent의 상장을 계기로 본 실시간 데이터 스트리밍이 기업 비즈니스에 미치는 영향과 미래 가치를 조망합니다.
    *   **발표 3단 구조:**
        *   **문제:** 하루 단위로 데이터를 처리하는 배치 방식으로는 실시간 추천, 사기 탐지 등 급변하는 비즈니스 환경에 즉각적으로 대응할 수 없습니다.
        *   **근거:** '데이터 인 모션'은 데이터가 흐르는 과정에서 즉시 가치를 창출하여, 즉각적인 위협 탐지 및 개인화된 고객 경험 제공을 가능하게 합니다. (컨테이너 이상탐지, 금융 FDS 사례)
        *   **제언:** 모든 기업은 비즈니스 프로세스에서 발생하는 이벤트를 실시간으로 포착하고 대응하는 '이벤트 기반 아키텍처'로의 전환을 통해 새로운 가치 창출 기회를 모색해야 합니다.

### 9. 예상 질문 + 모범답안
*   **질문 1: 데이터 레이크와 데이터 웨어하우스의 차이점을 설명하고, 레이크하우스가 이 둘의 한계를 어떻게 극복하는지 설명해 주십시오.**
    네, 데이터 웨어하우스는 분석에 용이하도록 잘 정제된 '정형 데이터'를 저장하는 깨끗한 창고와 같고, 데이터 레이크는 형태와 상관없이 모든 데이터를 원본 그대로 쌓아두는 거대한 호수와 같습니다. 레이크하우스는 이 둘의 장점을 합친 것인데요. 데이터 레이크의 저비용 저장 공간 위에 데이터 웨어하우스의 신뢰성과 관리 기능을 더한 아키텍처입니다. 제가 컨테이너의 시스템 콜 로그를 분석해 이상행위를 탐지하는 프로젝트를 했을 때, 비정형적인 로그 데이터는 '레이크'에 가깝고, 여기서 유의미한 위협 패턴을 찾기 위한 분석은 '웨어하우스'의 역할이었습니다. 레이크하우스는 이렇게 하나의 저장소에서 데이터의 유연성과 신뢰성을 모두 확보하여, 데이터 파이프라인의 복잡성을 줄이고 더 빠른 분석을 가능하게 하는 핵심적인 해결책이라고 생각합니다.

*   **질문 2: '데이터 인 모션'의 중요성이 부각되는 이유는 무엇이며, 실시간 데이터 처리가 필요한 비즈니스 사례를 본인의 경험과 연결하여 설명해 주십시오.**
    네, '데이터 인 모션'은 데이터가 저장되기를 기다리지 않고, 흐르는 과정에서 즉시 처리해 가치를 만드는 것을 의미합니다. 이는 하루 단위로 처리하던 기존 배치 방식으로는 불가능했던 즉각적인 의사결정을 가능하게 하기 때문에 중요합니다. 제가 수행했던 컨테이너 보안 프로젝트가 '데이터 인 모션'의 좋은 예시라고 생각합니다. 커널에서 발생하는 초당 수만 개의 시스템 콜 이벤트를 실시간 스트림으로 간주하고, 이 데이터가 디스크에 저장되기도 전에 패턴을 분석해 비정상 행위를 즉시 탐지해야 했습니다. 이처럼 즉각적인 대응이 생명인 보안 관제, 금융 사기 탐지, 실시간 추천 시스템 분야에서 '데이터 인 모션'의 가치는 더욱 커질 것입니다.

*   **질문 3: 데이터 메시 아키텍처가 기존 중앙 집중식 데이터 관리 방식과 비교했을 때 가지는 장점과, 발생할 수 있는 문제점은 무엇이라고 생각하십니까?**
    데이터 메시는 데이터의 소유권을 현업 도메인 팀에 부여하여, 중앙 팀의 병목을 해결하고 비즈니스 변화에 민첩하게 대응할 수 있다는 큰 장점이 있습니다. 하지만 데이터 거버넌스가 여러 팀으로 분산되면서 전사적인 데이터 일관성을 유지하기 어렵고, 보안 관리가 파편화될 수 있다는 문제점이 있습니다. 예를 들어, 제 전공인 시스템 콜 로그 같은 민감한 보안 데이터를 각 서비스팀이 '데이터 제품'으로 만들어 관리한다고 가정해 보겠습니다. 만약 팀마다 데이터 정제 수준이나 접근 제어 정책이 다르다면, 전사적인 보안 태세를 통합적으로 관제하기가 매우 어려워질 것입니다. 따라서 성공적인 데이터 메시 도입을 위해서는 분산된 자율성과 중앙의 강력한 거버넌스 철학이 균형을 이루어야 한다고 생각합니다.

*   **질문 4: 클라우드 기반 데이터 플랫폼이 성장하면서, 보안 측면에서 어떤 고려사항이 가장 중요하다고 생각하며, 본인은 어떻게 기여할 수 있습니까?**
    네, 클라우드 데이터 플랫폼에서는 데이터에 접근하는 '행위' 자체를 실시간으로 분석하는 '행위 기반 보안'이 가장 중요하다고 생각합니다. 기존의 정적인 접근 제어만으로는 내부자 위협이나 탈취된 계정을 이용한 데이터 유출을 막기 어렵기 때문입니다. 저는 컨테이너 환경에서 시스템 콜(syscall)을 동적 관측하여 정상 행위 프로파일을 만들고, 이를 벗어나는 이상 행위를 탐지하는 프로젝트를 수행한 경험이 있습니다. 이 경험을 바탕으로, 데이터 플랫폼 사용자의 쿼리 패턴이나 데이터 접근 행위를 실시간으로 분석하여 비정상적인 활동을 조기에 차단하는 런타임 보안 체계를 구축하는 데 기여하고 싶습니다. 이는 리눅스 커널 수준의 이해를 바탕으로 한 저의 강점을 가장 잘 발휘할 수 있는 분야라고 확신합니다.

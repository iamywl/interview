## 2024 · 오픈소스 · 개발자 생태계

### 1. 그해 핵심 트렌드
2024년은 **공급망 보안 위기의 재현**과 **라이선스 포크의 일상화**, 그리고 **AI 코딩의 폭발**이 동시에 일어난 해다. 3월 xz Utils 백도어(CVE-2024-3094)가 Log4Shell 이후 최대 공급망 공격으로 기록됐고, 같은 달 Redis가 BSD를 버리고 SSPL/RSALv2로 전환하자 Linux Foundation이 Valkey로 즉각 포크했다. AI 영역에서는 Meta Llama 3.1 405B가 첫 프런티어급 오픈 가중치 모델로 공개됐고, Cursor 같은 AI 코딩 에디터가 폭발적으로 성장했다.

### 2. 대표 뉴스·사건
- **xz Utils 백도어 발견(CVE-2024-3094)**: 2024년 3월 29일 Microsoft 엔지니어 Andres Freund가 PostgreSQL 벤치마크 중 SSH 로그인이 비정상적으로 느린 것을 발견해 liblzma 백도어를 찾아냈다. 다년간의 사회공학으로 유지보수 권한을 얻은 'Jia Tan' 계정이 심은 OpenSSH 인증 우회 RCE였다 ([CrowdStrike, 2024-03](https://www.crowdstrike.com/en-us/blog/cve-2024-3094-xz-upstream-supply-chain-attack/)).
- **xz 백도어의 배포 범위와 대응**: 백도어는 Fedora 40 beta·Rawhide, Debian unstable/testing, Kali, Arch 등 개발 버전에 포함됐고, Red Hat·SUSE·Debian이 24시간 내 패키지를 되돌렸으며 CISA가 즉시 롤백을 권고했다 ([Qualys, 2024-03-29](https://blog.qualys.com/vulnerabilities-threat-research/2024/03/29/xz-utils-sshd-backdoor)).
- **Redis 라이선스 전환**: 2024년 3월 20일 Redis가 15년간의 BSD 3-clause를 버리고 SSPLv1·RSALv2 이중 소스 가용 라이선스로 전환했다 ([SoftwareSeni](https://www.softwareseni.com/the-redis-valkey-fork-how-enterprises-rapidly-migrated-after-the-sspl-license-change/)).
- **Valkey 포크 출범**: 2024년 4월 1일 Linux Foundation이 Redis 7.2.4를 기반으로 한 BSD 라이선스 포크 Valkey를 AWS·Google Cloud·Oracle 지원으로 출범했다. 중립적 TSC 거버넌스로 단일 벤더 통제를 차단했다 ([SoftwareSeni](https://www.softwareseni.com/the-redis-valkey-fork-how-enterprises-rapidly-migrated-after-the-sspl-license-change/)).
- **Meta Llama 3.1 405B 공개**: 2024년 7월 23일 Meta가 4050억 파라미터 모델 Llama 3.1 405B를 공개했다. 15조 토큰 이상으로 1만 6천 개 이상 H100 GPU에서 학습한, 첫 프런티어급 오픈 가중치 모델로 평가됐다 ([TechCrunch, 2024-07-23](https://techcrunch.com/2024/07/23/meta-releases-its-biggest-open-ai-model-yet/)).
- **Cursor(Anysphere) 급성장**: 2024년 8월 Cursor가 a16z·Thrive Capital 등으로부터 6천만 달러 시리즈 A를, 연말 약 26억 달러 가치에 1억 500만 달러 시리즈 B를 유치하며 AI 코딩 에디터 붐을 이끌었다 ([SiliconANGLE, 2024-12-20](https://siliconangle.com/2024/12/20/anysphere-reportedly-raises-100m-ai-driven-cursor-code-editor/)).

### 3. 핵심 기업·제품·기술 키워드
- **공급망 보안**: xz Utils, CVE-2024-3094, liblzma, OpenSSH 백도어, 유지보수자 번아웃, SBOM
- **라이선스·포크**: Redis SSPL/RSALv2, Valkey, BSD, OpenTofu, Linux Foundation
- **오픈 LLM**: Meta Llama 3.1 405B, 128K 컨텍스트, Hugging Face
- **AI 코딩**: Cursor, Anysphere, GitHub Copilot, AI 코드 에디터

### 4. 시장 수치·전망
- AI 코딩 도구 시장은 2024년 약 49억 달러 규모로, 2032년 300억 달러 초과 전망(CAGR 약 27.1% 추정) ([Contrary Research](https://research.contrary.com/company/cursor)).
- Valkey는 출범 수 주 내 50개 이상 기여 기업·150명 이상 개인 기여자·1000개 이상 커밋 확보 ([SoftwareSeni](https://www.softwareseni.com/the-redis-valkey-fork-how-enterprises-rapidly-migrated-after-the-sspl-license-change/)).
- Llama 3.1 405B: 4050억 파라미터, 128K 컨텍스트, 15조+ 토큰 학습 ([TechCrunch, 2024-07-23](https://techcrunch.com/2024/07/23/meta-releases-its-biggest-open-ai-model-yet/)).

### 5. 전년 대비 변화점
- **새로 뜬 것**: 사회공학으로 유지보수 권한을 탈취하는 신종 공급망 공격(xz), 라이선스 전환→즉각 포크의 표준화(Valkey), 프런티어급 오픈 가중치 모델(405B), AI 코딩 에디터 전문 스타트업(Cursor).
- **식은 것**: "신뢰받는 유지보수자가 안전하다"는 가정. xz 사건으로 유지보수자 신원·번아웃·거버넌스 리스크가 핵심 의제가 됐다.

### 6. PT 발표 주제 후보
- **xz 백도어가 드러낸 오픈소스의 인적 리스크**: 코드가 아니라 사람(유지보수자)을 노린 다년간 공급망 공격의 교훈.
- **라이선스 전환과 포크의 시대**: Redis→Valkey로 본 오픈소스 거버넌스의 자기 복원력.
- **오픈 가중치 프런티어 모델의 등장**: Llama 3.1 405B가 바꾼 폐쇄형 vs 개방형 AI 균형.

### 7. 예상 꼬리질문 + 답변 포인트
- **Q. xz 백도어 같은 공격을 런타임에서 탐지할 수 있나?**
  A. xz 백도어는 sshd가 liblzma를 로드할 때 인증 흐름을 변조했다. 정적 분석은 난독화된 빌드 산물 때문에 놓치기 쉽다. 제가 다룬 시스템 콜 동적 관측 기반 이상탐지를 적용하면, sshd가 평소와 다른 함수 호출·메모리 접근·자식 프로세스를 만들 때 행위 기반으로 이상을 포착할 수 있다. 실제로 발견의 단서도 "비정상적으로 느린 SSH 응답"이라는 런타임 관측이었다.
- **Q. Linux 배포판의 패키지 신뢰성을 어떻게 확보하나?**
  A. 재현 가능한 빌드(reproducible builds)로 소스와 바이너리의 일치를 검증하고, 메인테이너 다양화·서명 검증·SBOM으로 공급망 가시성을 높인다. xz 사건은 단일 유지보수자 의존과 git 저장소에 없던 릴리스 tarball의 위험을 보여줬다. Linux 커널·시스템 레벨을 이해하는 입장에서, 빌드 파이프라인의 무결성 검증이 가장 실효적이라고 본다.
- **Q. 오픈 가중치 모델이 보안에 주는 함의는?**
  A. 405B 같은 모델을 사내에서 직접 호스팅하면 데이터 외부 유출 위험은 줄지만, 모델 가중치 자체가 공급망 자산이 된다. 출처·해시 검증과 추론 컨테이너 격리가 필요하고, 컨테이너 보안 관점에서 추론 워크로드의 비정상 시스템 콜을 모니터링해 모델 악용·탈취를 탐지해야 한다.

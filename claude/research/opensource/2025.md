## 2025 · 오픈소스 · 개발자 생태계

### 1. 그해 핵심 트렌드
2025년은 **오픈 가중치 LLM이 비용·성능 판도를 흔들고**, **라이선스 회귀가 일어난** 해다. 1월 중국 DeepSeek가 R1을 MIT 라이선스로 공개하며 저비용 추론 모델로 시장에 충격을 줬다. 동시에 1년간 SSPL로 떠났던 Redis가 5월 AGPLv3로 복귀해 "OSI 승인 오픈소스"로 돌아왔다. 반면 IBM은 2월 HashiCorp를 64억 달러에 인수했지만 Terraform의 BSL을 유지하며 OpenTofu와의 분기가 고착됐다. AI 코딩 에디터(Cursor)는 폭발적 매출 성장을 이어갔다.

### 2. 대표 뉴스·사건
- **DeepSeek-R1 오픈 공개**: 2025년 1월 20일 DeepSeek가 추론 모델 R1을 MIT 라이선스로 공개했다. 코드·가중치 모두 상업적 사용·수정·증류(distillation)를 허용했고, Qwen·Llama 기반 1.5B~70B 증류 모델 6종도 함께 풀었다 ([DeepSeek API Docs, 2025-01-20](https://api-docs.deepseek.com/news/news250120)).
- **DeepSeek 시장 충격**: 저비용으로 프런티어급 추론 성능을 낸 R1의 등장은 폐쇄형 모델 중심 시장에 큰 파장을 일으켰고, 오픈 가중치 모델의 경쟁력을 재확인시켰다 ([Wikipedia — DeepSeek](https://en.wikipedia.org/wiki/DeepSeek)).
- **IBM, HashiCorp 인수 완료**: 2025년 2월 27일 IBM이 64억 달러에 HashiCorp 인수를 마무리했다. 미국 FTC와 영국 CMA가 승인했으나, 인수 후에도 Terraform·Vault의 라이선스는 BSL로 유지돼 오픈소스 복귀 여부에 불확실성이 남았다 ([TechCrunch, 2025-02-27](https://techcrunch.com/2025/02/27/ibm-closes-6-4b-hashicorp-acquisition/)).
- **Redis AGPLv3 복귀**: 2025년 5월 Redis가 Redis 8 정식 출시와 함께 AGPLv3를 추가 라이선스로 채택하며 OSI 승인 오픈소스로 복귀했다. SSPL이 오픈소스로 인정받지 못한 점을 이유로 들었다 ([The Register, 2025-05-01](https://www.theregister.com/2025/05/01/redis_returns_to_open_source/)).
- **Redis 창립자 복귀와 Redis 8**: Redis가 창립자 Salvatore Sanfilippo를 다시 영입했고, Redis 8은 벡터셋이라는 신규 데이터 타입과 JSON·Time Series·쿼리 엔진 등 Redis Stack 기술을 코어에 통합했다 ([InfoQ, 2025-05](https://www.infoq.com/news/2025/05/redis-agpl-license/)).
- **Valkey의 안착**: Redis가 오픈소스로 복귀했음에도, CNCF가 후원하는 Valkey가 AWS·Google Cloud 지원 속에 이미 자리를 잡아 다수 개발자가 Redis로 되돌아가지 않을 것이라는 전망이 우세했다 ([The New Stack, 2025](https://thenewstack.io/redis-is-open-source-again/)).

### 3. 핵심 기업·제품·기술 키워드
- **오픈 LLM**: DeepSeek-R1, MIT 라이선스, 추론 모델, 증류(distillation), Qwen/Llama 기반
- **라이선스 회귀**: Redis AGPLv3, OSI 승인, SSPL 철회, Redis 8(벡터셋)
- **M&A·거버넌스**: IBM-HashiCorp 64억 달러, BSL, OpenTofu, Valkey(CNCF)
- **AI 코딩**: Cursor(Anysphere), GitHub Copilot

### 4. 시장 수치·전망
- IBM의 HashiCorp 인수 규모 64억 달러(확정) ([TechCrunch, 2025-02-27](https://techcrunch.com/2025/02/27/ibm-closes-6-4b-hashicorp-acquisition/)).
- DeepSeek-R1 증류 모델 라인업: 1.5B/7B/8B/14B/32B/70B 6종, 모두 MIT 라이선스 ([DeepSeek API Docs, 2025-01-20](https://api-docs.deepseek.com/news/news250120)).
- Redis 8은 AGPLv3로 OSI 승인 라이선스 목록에 재진입(확정 사실) ([Redis Blog](https://redis.io/blog/agplv3/)).

### 5. 전년 대비 변화점
- **새로 뜬 것**: 저비용 오픈 추론 모델(DeepSeek-R1), 라이선스 "회귀"(Redis AGPL 복귀), 빅테크의 오픈소스 벤더 인수(IBM-HashiCorp).
- **식은 것**: SSPL의 정당성. Redis조차 SSPL을 철회하면서, "소스 가용(source-available)"이 "오픈소스"의 대안이 될 수 없다는 인식이 강해졌다. 단 포크(Valkey)는 이미 정착해 원본 복귀가 시장을 되돌리지 못했다.

### 6. PT 발표 주제 후보
- **DeepSeek-R1과 오픈 추론 모델의 충격**: 저비용 오픈 가중치 모델이 흔든 글로벌 LLM 경제학.
- **라이선스 회귀의 교훈**: Redis의 SSPL→AGPL 복귀가 보여준 "포크는 되돌릴 수 없다".
- **빅테크가 산 오픈소스의 운명**: IBM-HashiCorp 인수 후 Terraform/OpenTofu 분기 고착.

### 7. 예상 꼬리질문 + 답변 포인트
- **Q. DeepSeek 같은 오픈 가중치 모델을 사내에서 쓸 때 보안 점검 사항은?**
  A. 가중치 출처·해시 검증이 1순위다. MIT 라이선스라 사용 제약은 적지만, 모델에 백도어된 동작이나 데이터 유출 가능성을 배제할 수 없다. 추론 컨테이너를 최소 권한·egress 통제로 격리하고, 제가 다룬 시스템 콜 동적 관측 기반 이상탐지로 추론 워크로드의 비정상 외부 연결·파일 접근을 행위 기반으로 모니터링하면 모델 자체의 리스크를 줄일 수 있다.
- **Q. AGPL과 SSPL의 차이가 왜 중요한가?**
  A. AGPL은 OSI가 승인한 오픈소스 라이선스로, 네트워크로 제공할 때 소스 공개 의무를 지운다. SSPL은 그 의무를 "관련 서비스 전체"로 확장해 사실상 클라우드 사업자를 배제하려 했고, 그래서 OSI 승인을 받지 못했다. 의존성을 채택하는 풀스택 개발자 입장에서, AGPL은 사내 SaaS 제공 시 소스 공개 의무를 유발할 수 있으므로 라이선스 조항을 반드시 검토해야 한다.
- **Q. 원본(Redis)이 오픈소스로 돌아와도 포크(Valkey)가 살아남는 이유는?**
  A. 포크가 중립적 거버넌스(CNCF·TSC)와 클라우드 사업자 지원을 확보하면, 이미 이전한 사용자에게는 되돌아갈 유인이 적다. 신뢰는 한 번 깨지면 회복 비용이 크다. 이는 컨테이너·인프라 도구 선택에서도 마찬가지로, 단일 벤더 통제 리스크를 거버넌스 구조로 평가해야 한다는 점을 보여준다.

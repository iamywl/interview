## 2022 · AI 에이전트 · 에이전틱 AI

### 1. 한눈에 보기
2022년은 AI 에이전트가 폭발하기 직전, 모든 기술적·이론적 기반이 마련된 '준비의 해'였습니다. LLM이 단순히 텍스트를 생성하는 것을 넘어, 외부 도구를 활용해 '생각하고 행동하는' ReAct 패러다임이 정립되었습니다. LangChain 같은 프레임워크는 이런 아이디어를 실제 코드로 쉽게 구현할 길을 열었고, 연말에 등장한 ChatGPT는 강력한 LLM을 누구나 사용할 수 있게 하여 2023년 자율 에이전트 혁명의 기폭제가 되었습니다.

### 2. 그해 핵심 트렌드
- **"추론하며 행동하는" LLM 패러다임의 정립:** 단순히 텍스트를 생성하던 기존 LLM을 넘어, 생각(reasoning)과 외부 도구 실행(acting)을 번갈아 수행하는 ReAct(Reasoning + Acting) 구조가 학계에서 제시되며 현대 에이전트 루프의 핵심적인 표준으로 자리매김했습니다.
- **LLM을 외부 도구와 결합하려는 신경-기호(Neuro-Symbolic) 접근 강화:** AI21 Labs의 MRKL 시스템이 LLM의 계산 및 최신 지식 한계를 외부 전문 모듈로 보완하는 아키텍처를 제시하며, 'LLM + 도구 호출'이라는 에이전트의 핵심적인 설계 방향을 제시했습니다.
- **에이전트를 효율적으로 조립하는 오픈소스 프레임워크의 등장:** LangChain이 LLM을 프롬프트 템플릿, 도구, 체인 등으로 엮는 추상화 계층으로 처음 공개되었으며, 이후 ReAct 기반의 에이전트 기능을 통해 LLM과 외부 도구 및 데이터베이스 연결을 표준화하는 기반을 제공했습니다.
- **자연어로 소프트웨어 조작이 가능한 "행동 파운데이션 모델" 스타트업의 출현:** Transformer 논문 공동 발명자들이 설립한 Adept는 ACT-1 모델을 통해 자연어 지시만으로 웹 브라우저나 애플리케이션을 다단계로 조작할 수 있음을 시연하며, LLM이 '말'을 넘어 '행동'으로 나아갈 수 있는 가능성을 보여주었습니다.
- **언어 모델과 로봇 제어의 성공적인 결합:** Google과 Everyday Robots의 PaLM-SayCan은 LLM의 방대한 상식(무엇을 해야 하는지)과 로봇의 실제 실행 가능성(무엇을 할 수 있는지)을 결합하여, LLM이 물리적 행동을 단계별로 계획하고 실행하도록 하는 데 성공하며 LLM의 적용 범위를 물리 세계로 확장했습니다.
- **RLHF 기반 지시 따르기(Instruction Following) 능력의 고도화:** OpenAI의 InstructGPT 및 GPT-3.5 계열(text-davinci-003)이 사람 피드백을 통한 강화학습(RLHF)을 통해 사용자 지시를 훨씬 더 정확하고 신뢰성 있게 따르는 능력을 확보했습니다. 이는 이후 ChatGPT의 대중화와 에이전트가 사용자의 복잡한 지시를 안정적으로 수행하는 데 필수적인 기반 기술이 되었습니다.

### 4. 신기술 개념설명
**1. ReAct (Reasoning + Acting, 추론-행동 교차 루프)**
- **(1) 한 줄 정의:** LLM이 '생각(Thought)-행동(Action)-관찰(Observation)'의 순환 고리를 통해 스스로 추론하고, 외부 도구를 사용하며, 그 결과를 바탕으로 다음 계획을 수정해 나가는 문제 해결 방식입니다.
- **(2) 왜 나왔나:** 기존 LLM은 학습된 데이터에만 의존해 사실과 다른 내용을 그럴듯하게 지어내는 '환각' 문제가 심각했습니다. 또한, 한번 잘못된 추론을 시작하면 그 오류가 계속 누적되어 결국 작업 전체를 실패로 이끄는 한계가 있었습니다.
- **(3) 어떻게 동작하나:** 목표가 주어지면, 먼저 LLM은 'Thought'를 통해 문제 해결 계획을 세웁니다. 그 계획에 따라 필요한 'Action'(예: 웹 검색 API 호출)을 실행하고, 그 결과로 얻어진 'Observation'(예: 검색 결과 텍스트)을 확인합니다. 그리고 이 관찰 결과를 바탕으로 다시 'Thought'를 수정하거나 다음 계획을 세우는 과정을 목표를 달성할 때까지 반복합니다.
- **(4) 무엇이 달라지나:** LLM이 막연한 내부 지식이 아닌 외부 세계의 실제 데이터로 자신의 판단을 검증하고 교정할 수 있게 됩니다. 이 덕분에 환각이 크게 줄고, 복잡한 문제 해결 능력이 향상됩니다. 또한 모든 추론과 행동 과정이 기록으로 남아, 왜 AI가 그런 결정을 내렸는지 사람이 추적하고 디버깅하기 쉬워져 신뢰성이 높아집니다.

**2. 행동 파운데이션 모델 (Action Foundation Model)**
- **(1) 한 줄 정의:** Adept의 ACT-1처럼, 자연어 명령을 이해하고 텍스트가 아닌 '소프트웨어 조작'(클릭, 타이핑 등)을 순서대로 출력하여 실제 컴퓨터 작업을 대신 수행하는 AI 모델입니다.
- **(2) 왜 나왔나:** 기존 LLM은 "엑셀을 열고, A열의 합계를 구해서, 결과 값을 슬랙으로 보내줘"라고 지시하면 "네, 그렇게 하시면 됩니다"라고 방법을 알려줄 뿐, 직접 작업을 수행해주지는 못했습니다. 이 '말'과 '행동' 사이의 간극을 메워 진정한 업무 자동화를 구현하기 위해 등장했습니다.
- **(3) 어떻게 동작하나:** 사람이 특정 소프트웨어를 사용하는 화면과 행동(클릭, 키보드 입력)을 대규모로 녹화한 데이터를 학습합니다. 이후 사용자가 자연어로 "고객 목록을 최신순으로 정렬해줘"라고 명령하면, 모델은 현재 화면(UI)을 인식하고, '정렬' 버튼의 위치를 찾아 클릭하는 등의 행동 시퀀스를 생성하여 운영체제(OS) 수준에서 직접 실행합니다.
- **(4) 무엇이 달라지나:** AI가 단순한 정보 검색 도구를 넘어, 사람의 디지털 업무를 대신하는 '가상 비서'나 '소프트웨어 로봇'이 될 수 있는 가능성을 열었습니다. 하지만 이는 AI에게 실제 시스템의 '실행 권한'을 주는 것으로, 잘못된 행동 하나가 시스템 전체에 심각한 문제를 일으킬 수 있어 강력한 보안 및 격리 기술이 반드시 함께 고려되어야 하는 중요한 과제를 남겼습니다.

### 7. 전년 대비 변화점
- **새로 뜬 것 — 추론-행동 루프(ReAct)와 에이전트 프레임워크(LangChain)의 등장:** 2021년까지 LLM 연구는 주로 '더 정교하고 유려한 텍스트 생성'에 초점을 맞췄지만, 2022년에는 ReAct를 통해 LLM이 '생각'과 '외부 도구 활용'을 순환적으로 연결하는 이론적 기반이 마련되었습니다. 동시에 LangChain과 같은 프레임워크가 등장하여 이러한 이론을 실제 에이전트로 쉽게 구현할 수 있는 도구적 기반을 제공하며, LLM 활용의 패러다임을 근본적으로 변화시키기 시작했습니다.
- **새로 뜬 것 — 도구 사용형 신경-기호 사고(MRKL)의 명확화:** "LLM의 한계를 외부 전문 도구로 보완한다"는 개념이 AI21 Labs의 MRKL 시스템을 통해 명확한 아키텍처와 함께 제시되었습니다. 이는 LLM이 모든 것을 혼자 해결하는 것이 아니라, 필요에 따라 외부의 '전문가' 도구를 활용하여 문제 해결 능력을 확장하는 새로운 접근법을 확립했습니다.
- **강해진 것 — 자연어로 소프트웨어·로봇을 조작하려는 실질적인 시도:** Adept의 ACT-1이 웹/앱 환경에서, Google의 PaLM-SayCan이 물리적 로봇 환경에서 자연어 지시를 받아 직접 '행동'하는 모습을 구체적으로 시연하면서, LLM의 적용 범위가 단순히 텍스트를 생성하는 것에서 실제 세계의 작업을 자동화하는 방향으로 크게 확장될 수 있음을 보여주었습니다.
- **강해진 것 — RLHF 기반 지시 따르기 능력의 압도적 성숙:** OpenAI의 InstructGPT에서 text-davinci-003, 그리고 결정적으로 ChatGPT로 이어지는 과정에서 사람 피드백을 활용한 강화학습(RLHF) 기술이 크게 발전했습니다. 이는 LLM이 사용자의 복잡하고 미묘한 지시를 훨씬 더 정확하고 일관되게 따를 수 있게 만들었으며, 에이전트가 신뢰성 있게 작업을 수행하는 데 필수적인 기반이 되었습니다.
- **식은 것 — "더 큰 단일 모델이면 모든 문제가 해결된다"는 관점의 한계 부각:** MRKL 시스템과 ReAct 패턴의 등장은 단순히 LLM의 크기를 키우는 것만으로는 계산 오류, 최신 정보 부족, 환각과 같은 근본적인 한계를 해결하기 어렵다는 인식을 확산시켰습니다. 이에 따라, 단일 거대 모델보다는 'LLM + 외부 도구 조합'을 통한 문제 해결 방식으로 무게 중심이 이동하기 시작했습니다.
- **결정적 전환 — ChatGPT의 공개와 LLM의 대중화:** 2022년 말 ChatGPT의 무료 공개는 고품질 LLM에 대한 대중과 개발자 커뮤니티의 접근성을 혁신적으로 높였습니다. 이는 ReAct나 LangChain과 같은 선행 기술들이 존재했음에도 불구하고, 실제 자율 에이전트가 폭발적으로 발전하고 확산되는 데 필요한 마지막 퍼즐 조각이자 직접적인 기폭제 역할을 했습니다.

### 8. PT 발표 주제 후보
**후보 1. "생각하고 행동하는 AI의 설계 원형: ReAct가 연 에이전트 시대"**
- **한 줄 메시지:** 2022년 제시된 ReAct는 LLM의 환각을 줄이고 신뢰도를 높여, '추론'과 '행동'을 연결하는 현대 AI 에이전트의 근본적인 설계 원형을 확립했습니다.
- **발표 3단 구조:**
    - **문제:** LLM은 그럴듯하게 거짓말(환각)을 하고, 복잡한 문제 해결에 실패하는 명확한 한계가 있었습니다.
    - **근거:** ReAct는 '생각-행동-관찰'의 순환 고리를 통해 LLM이 외부 도구로 실제 정보를 확인하고, 자신의 추론을 스스로 교정하게 함으로써 이 문제를 해결했습니다.
    - **제언:** ReAct는 LLM을 단순 언어 생성기를 넘어 신뢰할 수 있는 문제 해결 파트너로 만드는 핵심 열쇠이며, 모든 자율 에이전트 개발의 출발점이 되어야 합니다.

**후보 2. "말에서 행동으로: 행동형 AI의 부상과 안전한 통제라는 새로운 과제"**
- **한 줄 메시지:** 2022년 Adept ACT-1 등의 등장은 AI가 실제 소프트웨어를 조작하는 '행동 에이전트' 시대를 열었지만, 이는 강력한 보안 및 격리 기술 없이는 큰 위험을 초래할 수 있습니다.
- **발표 3단 구조:**
    - **문제:** 기존 AI는 '답'만 줄 뿐, 실제 업무를 대신해주지 못해 생산성 향상에 한계가 있었습니다.
    - **근거:** Adept ACT-1, Google PaLM-SayCan은 AI가 자연어 명령만으로 웹 브라우저나 로봇을 직접 조작할 수 있음을 보여주며 이 문제를 해결할 가능성을 제시했습니다.
    - **제언:** 에이전트에게 시스템 실행 권한을 주기 위해서는, 제가 경험한 컨테이너 기반의 격리 환경과 시스템 콜 동적 관측을 통한 이상 행위 탐지 같은 강력한 '가두고 관찰하는' 보안 아키텍처가 반드시 선행되어야 합니다.

**후보 3. "ChatGPT, 에이전트 혁명의 마지막 퍼즐 조각"**
- **한 줄 메시지:** 2022년 말 ChatGPT의 등장은 강력한 LLM의 대중화를 통해, 이미 존재하던 ReAct, LangChain 같은 기술들이 폭발적으로 결합하고 성장하는 결정적인 기폭제 역할을 했습니다.
- **발표 3단 구조:**
    - **문제:** ReAct, LangChain 등 에이전트의 핵심 이론과 도구는 있었지만, 이를 활용할 강력하고 접근성 높은 LLM이 없어 소수 연구자들의 기술로 남아있었습니다.
    - **근거:** ChatGPT가 전 세계에 무료로 공개되자, 수많은 개발자들이 이를 활용해 단 몇 달 만에 AutoGPT와 같은 자율 에이전트 프로젝트들을 쏟아내며 기술 확산을 주도했습니다.
    - **제언:** 진정한 기술 혁신은 뛰어난 기술 하나가 아니라, 강력한 기반 기술(LLM)과, 그것을 활용하는 이론(ReAct), 그리고 구현 도구(LangChain)가 만나 대중화될 때 비로소 완성됩니다.

### 9. 예상 질문 + 모범답안
**1. ReAct 패턴을 설명하고, 왜 현대 에이전트 설계의 핵심이 되었는지 본인의 경험에 빗대어 설명해보세요.**
네, ReAct는 LLM이 'Thought(생각)'로 계획을 세우고, 'Action(행동)'으로 외부 도구를 실행한 뒤, 그 결과인 'Observation(관찰)'으로 계획을 수정하는 순환 패턴입니다. 이 패턴의 핵심은 LLM이 외부의 실제 데이터로 자신의 추론을 검증한다는 점입니다. 제가 컨테이너 보안을 위해 시스템 콜을 동적으로 관측해 이상 행위를 탐지하는 프로젝트를 수행했는데, 이때 '시스템 콜 관측(Observation) → 정상/비정상 행위 판단(Thought) → 의심 프로세스 추적 강화 또는 차단(Action)'을 반복하는 구조를 설계했습니다. 이 경험을 통해 ReAct처럼 관찰-판단-행동의 피드백 루프가 환각과 오류를 줄이고, 의사결정 과정을 투명하게 만들어 시스템의 신뢰도를 높이는 데 결정적이라는 것을 체감했습니다. 이것이 ReAct가 현대 에이전트 설계의 핵심으로 자리 잡은 이유라고 생각합니다.

**2. LangChain 같은 에이전트 프레임워크를 사용할 때 발생할 수 있는 가장 큰 보안 위협은 무엇이며, 어떻게 막을 수 있을까요?**
가장 큰 보안 위협은 '프롬프트 인젝션'을 통해 에이전트가 의도치 않은 시스템 명령어를 실행하게 만드는 것입니다. 예를 들어, 웹사이트 내용을 요약해달라는 요청에 악성 스크립트를 숨겨두면, 에이전트가 이를 인지하지 못하고 실행하여 시스템 파일을 삭제하거나 정보를 유출할 수 있습니다. 이를 막기 위해 저는 제가 경험한 컨테이너 기반 보안 설계를 적용해야 한다고 생각합니다. 에이전트가 실행되는 환경 자체를 리눅스 네임스페이스와 cgroup으로 격리된 컨테이너 안에 가두고, 허용된 최소한의 기능만 수행하도록 권한을 제한합니다. 그리고 컨테이너 내부에서 발생하는 모든 시스템 콜과 네트워크 API 호출을 실시간으로 감시하여, 허용 목록에 없는 비정상적인 행위가 탐지되면 즉시 차단하는 '제로 트러스트' 아키텍처를 구축하는 것이 근본적인 해결책이 될 것입니다.

**3. 행동형 에이전트를 안전하게 운영하기 위해 어떤 기술이 필요한지, 본인의 리눅스 커널 지식과 연계하여 설명해주세요.**
행동형 에이전트의 잘못된 판단은 실제 시스템에 피해를 주므로, 저는 '가두고, 제한하고, 관찰하는' 세 가지 단계의 안전장치가 필요하다고 봅니다. 첫째, '가두기' 위해 리눅스 커널의 네임스페이스와 cgroup을 활용한 컨테이너 기술로 에이전트의 활동 공간을 호스트 시스템과 완벽히 격리해야 합니다. 둘째, '제한하기' 위해 AppArmor나 SELinux 같은 커널 보안 모듈을 이용해 에이전트가 접근할 수 있는 파일과 실행할 수 있는 명령어 종류를 최소한으로 줄여야 합니다. 마지막으로, '관찰하기' 위해 제가 프로젝트에서 활용했던 시스템 콜 동적 관측 기법을 적용해야 합니다. 커널의 eBPF 같은 기술을 사용하면 에이전트의 모든 시스템 레벨 행위를 오버헤드 없이 추적하고, 정해진 패턴을 벗어나는 이상 행위를 실시간으로 탐지하여 자동으로 차단하는 강력한 보안 모니터링 시스템을 구축할 수 있습니다.

**4. SSAFY의 풀스택 교육과 본인의 커널 지식을 융합하여, 만들고 싶은 AI 에이전트 서비스가 있다면 무엇인가요?**
네, 저는 저의 커널 및 시스템 보안 지식과 SSAFY에서 배울 풀스택 개발 역량을 결합하여 'DevSecOps 자동화 에이전트'를 만들고 싶습니다. 이 에이전트는 운영 중인 서버의 시스템 콜을 실시간으로 감시하여 보안 이상 징후를 탐지하는 것이 시작입니다. 이상 행위가 발견되면, 에이전트는 자동으로 어떤 프로세스가 문제인지, 어떤 취약점과 관련 있는지 분석합니다. 여기까지가 저의 기존 경험 영역이라면, SSAFY에서 배울 파이썬, Django, DB 기술을 활용해 에이전트가 직접 Git 리포지토리에서 관련 소스 코드를 찾아내고, LLM을 통해 잠재적인 코드 수정안을 생성하여 개발자에게 제시하는 기능을 구현하고 싶습니다. 최종적으로는 이 모든 과정을 대시보드 웹 서비스로 시각화하여, 보안 위협 탐지부터 코드 패치 제안까지의 전 과정을 자동화하는 융합형 서비스를 완성하는 것이 목표입니다.

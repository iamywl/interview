## 2025 · AI 에이전트 · 에이전틱 AI

### 1. 그해 핵심 트렌드
- "에이전트의 해(year of agents)"로 불릴 만큼 자율 에이전트가 일반 사용자·기업에 본격 배포됐다. OpenAI Operator가 실제 웹 작업을 수행하는 소비자용 에이전트로 출시됐다.
- 표준 경쟁·수렴이 동시에 일어났다. OpenAI가 MCP를 공식 채택(Agents SDK·Responses API)하며 MCP가 사실상 도구 연결 표준으로 굳어졌고, Google은 에이전트 간 통신 표준 A2A(Agent2Agent)를 발표했다.
- 멀티 에이전트·상호운용이 화두가 됐다. 단일 에이전트를 넘어 여러 에이전트가 서로 발견·인증·협업하는 구조로 확장됐다.
- 중국발 범용 에이전트 Manus가 등장해 자율 작업 데모로 화제가 됐다.
- 에이전트 보안(프롬프트 인젝션, 권한 위임, 도구 호출 감사)이 핵심 리스크로 본격 논의됐다.

### 2. 대표 뉴스·사건
- OpenAI, 2025년 1월 23일 Operator 리서치 프리뷰 출시. GPT-4o의 시각 능력과 강화학습 추론을 결합한 CUA(Computer-Using Agent)로 브라우저를 보고 클릭·타이핑·스크롤해 온라인 작업을 자율 수행한다. ([OpenAI, 2025-01-23](https://openai.com/index/introducing-operator/))
- Manus, 2025년 3월 6일 초청제 베타 출시(Butterfly Effect). 이력서 심사·주식 분석 등을 자율 수행하는 데모가 20시간 만에 100만 조회를 넘으며 범용 에이전트로 주목받았다. ([Wikipedia - Manus](https://en.wikipedia.org/wiki/Manus_(AI_agent)))
- OpenAI, 2025년 3월 11일 Agents SDK와 Responses API 공개. 며칠 뒤 MCP를 공식 채택하고 MCP 운영위원회에 합류해, MCP가 도구 연결의 사실상 표준이 됐다. ([OpenAI, 2025-03](https://openai.com/index/new-tools-and-features-in-the-responses-api/))
- Google, 2025년 4월 9일 Google Cloud Next에서 Agent2Agent(A2A) 프로토콜 발표. 서로 다른 프레임워크의 에이전트가 발견·인증·협업하는 개방형 표준으로, 50개 이상 파트너와 함께 출범했다. ([Google Developers Blog, 2025-04-09](https://developers.googleblog.com/en/a2a-a-new-era-of-agent-interoperability/))
- OpenAI, 2025년 5월 21일 Responses API에 원격 MCP 서버 지원·이미지 생성·코드 인터프리터 등 추가. 에이전트가 외부 도구·데이터에 연결하는 기능을 표준화·확장했다. ([OpenAI, 2025-05-21](https://openai.com/index/new-tools-and-features-in-the-responses-api/))

### 3. 핵심 기업·제품·기술 키워드
- 기업·제품: OpenAI(Operator·CUA·Agents SDK·Responses API), Manus(Butterfly Effect), Google(A2A 프로토콜), Anthropic(MCP 표준 주도)
- 기술: Computer-Using Agent, MCP(도구 연결 표준), A2A(에이전트 간 통신, Agent Card·OAuth2·JSON-RPC), 멀티 에이전트 오케스트레이션
- 개념: 에이전트 상호운용성, 권한 위임, 인간 확인(human-in-the-loop) 게이트

### 4. 시장 수치·전망 (전망/추정)
- CUA(Operator) 벤치마크: OSWorld 38.1%(전체 컴퓨터 사용), WebArena 58.1%, WebVoyager 87% — 자율 작업 성공률은 아직 사람 수준에 못 미침을 보여준다. ([OpenAI - CUA](https://openai.com/index/computer-using-agent/))
- A2A는 2025년 4월 50개 이상 파트너로 출범, 이후 Linux Foundation 거버넌스로 이관되며 빠르게 확산(추정). ([Google Developers Blog, 2025-04-09](https://developers.googleblog.com/en/a2a-a-new-era-of-agent-interoperability/))
- Operator는 초기 월 200달러 ChatGPT Pro 사용자에게 제공 — 고비용 프리미엄으로 시작했다. ([OpenAI, 2025-01-23](https://openai.com/index/introducing-operator/))

### 5. 전년 대비 변화점
- 새로 뜬 것: 소비자용 자율 에이전트(Operator·Manus), 에이전트 간 통신 표준(A2A), MCP의 표준 지위 확정, 에이전트 개발 SDK.
- 강해진 것: 2024년의 단일 에이전트·도구 연결이 2025년 멀티 에이전트·상호운용으로 확장됐다.
- 식은 것: "한 모델이 모든 것"이라는 단일 에이전트 만능론은 약화되고, 표준 프로토콜로 연결된 협업 구조가 부상했다.

### 6. PT 발표 주제 후보
1. "Operator와 자율 웹 에이전트" — AI가 직접 브라우저를 조작해 작업을 끝내는 단계로 진입했으나, 벤치마크상 신뢰성은 아직 과제임을 짚는다.
2. "MCP vs A2A" — 도구 연결 표준(MCP)과 에이전트 간 통신 표준(A2A)이 동시에 정립되며 에이전트 생태계의 양대 프로토콜이 만들어졌다.
3. "멀티 에이전트 시대의 보안" — 에이전트가 서로 권한을 위임·협업하면서 프롬프트 인젝션·권한 오남용이 핵심 위협으로 부상했다.

### 7. 예상 꼬리질문 + 답변 포인트
1. Q: Operator 같은 컴퓨터 사용 에이전트의 가장 큰 위험은?
   - A: 화면·웹에 숨은 지시를 따르는 프롬프트 인젝션, 그리고 잘못된 클릭으로 결제·삭제 같은 비가역 작업을 수행하는 위험입니다. 저는 컨테이너 격리와 런타임 시스템콜 관측 경험이 있어, 에이전트를 격리 환경에서 실행하고 민감 행위에 인간 확인 게이트를 두는 설계에 관심이 있습니다.
2. Q: A2A와 MCP의 차이를 설명하라.
   - A: MCP는 한 에이전트가 외부 도구·데이터에 연결하는 표준이고, A2A는 에이전트와 에이전트가 서로 발견·인증·협업하는 표준입니다. 둘 다 JSON-RPC 기반이며 상호 보완적입니다. 저는 표준 프로토콜 계층을 다뤄봐서, 표준화가 보안 감사 지점을 명확히 하는 이점에 주목합니다.
3. Q: 멀티 에이전트 시스템의 보안을 어떻게 설계하겠나?
   - A: 각 에이전트에 최소 권한을 부여하고, 에이전트 간 호출을 인증(OAuth·mTLS)하며, 도구 호출을 감사 로깅합니다. 저는 시스템콜 시퀀스로 이상 행동을 탐지한 경험이 있어, 에이전트 행동을 런타임에서 관측해 비정상 협업 패턴을 차단하는 접근이 효과적이라고 봅니다.
